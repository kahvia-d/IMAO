# 坐标／日期图像分区对照

接续真实张量对齐诊断，用户确认继续验证无需标签的坐标／日期图像分区。本轮完成了固定像素规则、同权重原生回放，以及观察到裁切错误后单独进行的保守支持策略对照。直接裁切能恢复不少日期边界导致的未返回，但会切掉数字并新增错误，因此淘汰；保守补充在较好的 v2 上只多救回一张雪地图，未作为正式方案采用。

没有继续训练、下载、改动生产 OCR 或解析器、替换客户端模型，也没有改标签或旧断言。本地证据位于 `C:\Dcode\WWMAP-TOOLS\out\coordinate-gap-study-20261015`。

## 固定分区规则

先在 27 张训练配对来源的实际 TopHat 预处理图上，仅检查像素空隙。没有将坐标文本、正确框、OCR 输出、相邻帧或小地图交给分区函数。观察到文字内部也可能存在假空隙，所以采用唯一明显空隙，否则保留整图；参数在开发回放前保存为 `rule-v1.json`，之后未调整。

规则针对现有固定 608×33 原始取景经 aspect 处理后的 892×48 图：检查 y=[5,39) 中大于 200 的像素列计数，每列不超过 2 个亮像素视作空列；候选起点在 x=[150,460]，连续宽度 24–64。最大候选必须比次大至少宽 8 像素。裁切点为候选起点加 8，右补 4 像素黑边。无候选或存在歧义时不裁切。规则依赖当前分辨率、字号和取景，不声称跨分辨率通用。

同一裁切点用于实际原生生成的 contrast、TopHat、raw 三张 PNG，随后直接交给未改动的 `CRNNRecognizer::Run`。没有先裁原图再重算 CLAHE，也没有用 Python 近似原生外围预处理。本轮唯一输入变化是这些 PNG 的右边界和补边。

346 个来源包含 170 张开发 XYZ、141 张无坐标、8 张待定，以及单列的 27 张已训练配对图。207 个来源应用裁切，139 个保持原图；开发部分应用 191 个，训练部分 16 个。776–787 草地组始终留出，12 张均由规则触发裁切。

## 两类失败的具体证据

- 第 1072 帧正确高度是 558。TopHat 抹去了高度末尾的亮笔画，检测到的“空隙”从图像 x=336 开始，裁切点 x=344 实际落在坐标内容内。裁后两个模型均返回 `-1064,-5581,55`。v2 分数约 0.967、v3 约 0.989，分数高也不能证明没有截断。原整图都因高度与日期粘连未返回。
- 第 771 帧的 TopHat 缺失高度 `-15` 的部分笔画，裁切点 x=222 位于高度之前。两个模型原整图单路线都正确，裁后只剩 `-582,-77,`，由正确变为未返回。
- 第 783 帧说明即使没有上述明显截断，短图也会改变识别。v2 裁后 TopHat 将 Z=-15 读成 -16，contrast 的 XY 仍相同，因此既有只核对 XY 的互证返回了错误 Z。第 777 帧也出现裁后 Z=-5；第 780 帧两路都丢 X 负号，互证不能纠正共同误读。

结论不是“日期裁掉就完成了”，而是日期上下文确实影响可用性，同时 TopHat 单图空隙不足以验证裁切安全，裁切后的识别与互证也需重新评测。

## 单独的保守补充对照

观察到上述失败后，没有回头调空隙阈值。另保存一份明确标为**事后探索**的策略：保留原整图 contrast-clock 已返回结果；只在整图未返回时，要求整图原始文本从开头能读出三个完整整数、与裁片已经通过旧解析器的 XYZ 完全一致，且整图分数达到 0.65，才接受裁片结果。

这个见证规则保留实际正负号、逗号和数字，不补字符；第三个整数必须与后文有边界，不能从 `5582026-...` 猜出 558。它是新的离线支持策略，不是原生产解析的既有行为；没有将其接入程序。完整图与裁片来自同一图片、同一模型，错误高度相关，不能称作独立真值互证。它也没有改动既有 contrast／TopHat 互证的 XY 语义。

| 单路线 | 原整图，正确 / 错误 / 未返回 | 保守补充后 | 雪地混合，正确 / 错误 / 未返回 |
|---|---|---|---|
| v2，170 张 | 161 / 1 / 8 | 162 / 1 / 7 | 35 / 0 / 5 → 36 / 0 / 4 |
| v3 预处理配对，170 张 | 128 / 1 / 41 | 145 / 1 / 24 | 29 / 0 / 11 → 33 / 0 / 7 |

新增返回在已标注开发图上均正确，无坐标仍为 0/141 误报。但 v2 只新增第 1070 帧一个正确返回；草地留出组仍为 11 正确、1 错误，没有改善。v3 新增 17 个开发正确返回，仍不如原 v2；另新增一张待定图的返回，不算正确。27 张训练来源另新增 5 个 v3 正确返回，不混入开发数字。第 1072 帧的截断误答在这个支持策略中保持未返回。

该支持策略是在查看本次开发错误后设计，不能将这批结果再当独立验证。它刻意保留整图已有返回，因此也保留已有错误，不能宣称解决了负号。

## 后续边界

本轮不推广直接裁切，也不把 +1 张开发正确作为替换正式管线的理由。继续微调前，应先有能检查文字完整性的取景方式，避免让模型学习“输入已切掉末位数字、标签仍保留”的不可能任务。下一步优先验证跨原图／对比度图的边界证据，并将取景安全与识别负号分别计分；这需要新的固定对照，不在已看过的开发集上反复调参并宣称泛化提升。现有素材足够继续定位问题，暂不要求用户补采同类负 X 草地。
