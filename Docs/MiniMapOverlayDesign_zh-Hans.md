# 小地图局部覆盖层（Mini Overlay）正式设计

> **状态：设计待评审，代码未动。** 依据是 `Docs/MinimapMarkerRenderPerfPlan_zh-Hans.md` §28 的实机 A/B/A/B 结果。
> 本文是"现行方案"，评审通过后随实现一起更新。

## 1. 已证结论（本轮实验数据）

同一次运行内 A/B/A/B（`full(0)` / `mini(128)`），场景基线 102 fps：

| | full | mini | 差 |
|---|---|---|---|
| FPS | 102.1 / 103.4 | **111.9 / 112.8** | **+9.6**（相对 ≈ +9.3%） |
| p95 | 12.49 / 12.04 | 9.84 / 9.75 | **−2.4 ms** |
| p99 | 14.50 / 14.33 | 10.86 / 10.65 | **−3.7 ms** |
| >20ms | 0.09% / 0.02% | **0 / 0** | → 0 |
| 窗口 / backbuffer | 2560×1440 | **355×344** | 面积的 3.3% |
| `segPresentMs` | 1.185 / 0.866 ms | **0.423 / 0.438 ms** | Present 长尾 40/32 ms → **2/1 ms** |
| `markerDrawMs` | 0.024 ms | 0.024 ms | 相同（同 1380 次绘制） |

机制：**收益在合成/present，不在 marker 绘制**；不是"少画了 marker"，也不是"少刷新了"（present 次数没减少）。
PresentMode 四段全是 `Composed: Flip` —— **不是**恢复了独立翻转。

## 2. 目标与非目标

**目标**：把"普通探索时用小窗口、开大地图用整屏"变成默认行为，且**不改变**坐标、定位、marker 语义与交互。

**非目标**（本轮明确不做）：重构大地图覆盖层、把 DirectComposition 变成默认、Texture Atlas、WGC ROI Readback、更换 GUI 框架。

## 3. 切换规则

| 状态 | 窗口 | 依据 |
|---|---|---|
| 普通探索（小地图可见、大地图未开、点位显示开） | **mini**（小地图矩形 + padding） | 已有 `frame.minimapVisible && !frame.mapVisible` |
| 大地图打开 | **整屏**（现状不变） | `frame.mapVisible` |
| 定位不可信 / 小地图缺失 | 保持 mini 尺寸但**不画 marker** | 现有 `ClearNearItemsData` 路径不变 |
| 游戏窗口最小化 / 失焦 | 沿用现状（`overlay-window-visibility` 的 idle 隐藏等） | 不改 |

窗口尺寸**只由游戏客户区尺寸 + DPI 决定，不由内容决定**：marker 有无、marker 数量都不触发改尺寸，避免尺寸抖动。

## 4. 几何与坐标系

沿用已实测通过的实现（`ImGuiOverWindows.cpp`）：

```text
MiniOverlayRect = (小地图矩形 + padding) ∩ 游戏客户区
padding         = clamp(客户区宽 × 0.025, 30, 60) px
```

- 小地图矩形来自 `GameWindowsScreenData::MinMapScreenData` 按客户区缩放（与其余 HUD 同一套换算）。
- **2560×1440 实测 = 355×344**，与公式预测一致。
- 绘制空间**仍是游戏客户区**：所有 marker / 路线 / 提示坐标含义不变；把顶点平移进小窗口（**不能**用 `DisplayPos`——本仓库 ImGui 把主 viewport 位置硬编码为原点，非零偏移会裁错）。
- 窗口跟随与缓冲区尺寸**复用** `OverlayWindowBounds`（未移动不调 `SetWindowPos`、按实际几何回读）与 `OverlayBackBufferSize`（自动把 SwapChain 调成窗口客户区）。
- 窗口样式不变 ⟹ **仍然完全鼠标穿透**。

## 5. 待决策项（需要你拍板）

### D1（最重要）游戏内状态栏怎么办

**事实**：你的设置里 `StatusBarEnabled = true`；状态栏画在客户区**顶部居中**（2560×1440、100% DPI 下宽 450 px，x≈1055–1505、y≈18–80），在 mini 矩形之外，所以**当前 mini 模式下它不可见**——A/B 那两段就是这么跑的，只是没被注意到。数据也证明它**不是**收益来源（marker 绘制耗时两模式相同、`segBuildMs` 未降）。

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A（推荐）并集窗口** | mini 矩形 ∪ 状态栏矩形 ⟹ 约 **1505×344（14% 面积）**，尺寸仍恒定（状态栏底边 80 < 344） | 窗口从 3.3% 涨到 14%，收益必然缩水但多少未知 | 需要**再测一次 A/B**才能知道还剩多少 |
| B 放弃状态栏 | 维持 355×344（3.3%） | 游戏内看不到定位/提示文字；只剩主窗口显示 | 与你当初"必须告诉玩家去开一次大地图"的要求冲突 |
| C 两个窗口 | 小地图窗口 + 状态栏窗口 | 多一个 HWND/SwapChain/present 路径 | 与"不要无需求的新架构"冲突，收益未知 |
| D 把状态栏搬进 mini 矩形 | mini 模式时状态栏画在小地图下方 | 文案最长约 450 px，355 宽会折行，矩形要加高 | 改变游戏内 UI 位置，属于 UX 决策 |

**我的建议：先测 A。** 方法现成：把并集窗口做成开关的第二个档位（或临时改一处常量），跑同场 `A/B/A/B` 看 14% 面积下的 FPS。若 A 的收益仍 ≥5 fps，就采用 A（零 UX 回归）；若掉到 1–2 fps，再在 B/D 之间选——那时是"要不要为了状态栏放弃一部分帧率"的取舍，应该由你定。

### D2 隔离开关怎么退场

- **做法（建议）**：**反转 bit 7 的语义**——`128` 从"启用 mini"改为"**强制整屏覆盖层**"；`0`（默认）= 生产行为（小地图 mini + 大地图整屏）。
  - 好处：不新增 bit（那个 NumberBox 上限刚改成 255，bit 0–7 已用满）、保留一键回滚与 A/B 能力、语义与"关闭某段工作"的其余 bit 一致（都是"关掉/强制某种做法"）。
  - 需要同步：诊断页文案（托管 `resources.pri`，本会话已验证该部署路径可用）与 `Measure-WorkIsolation.ps1 -Experiment mini-overlay` 的相位标签/掩码含义。
- **不做**：新增用户设置项（"小地图标记用独立小窗口"）——它要改设置页 + 托管重建，而本环境托管 shell 无法干净重建（`IMao-WinUI.csproj:161` 的既有 `MSB4186`，见台账 §26.1.1）。列为后续可选。

### D3 要不要"有 marker 才 mini"

**建议不要**。窗口尺寸跟内容走会在地图开合、玩家走动时反复改尺寸；空的小窗口是透明的，成本可忽略。

### D4 切换瞬间要不要去抖

**先测再决定**。大地图开/关会各触发一次 `ResizeBuffers`（`Ensure` 路径，之后 `hasPresented=false` 强制重画一帧）。要确认的是：切换前后是否有肉眼可见的一帧错位或闪烁、以及切换期间是否丢 marker。若一帧就位就不加去抖；若出现闪烁，再加"小地图状态稳定 N 帧后才缩窗口"的小延迟。

## 6. 切换过程的行为与风险

| 项 | 结论/待办 |
|---|---|
| 换尺寸的代价 | `OverlayBackBufferSize::Ensure` → `ResizeBuffers` → 强制一帧 present（现有路径，与游戏窗口缩放同一条代码） |
| 定位锚点保留 | `CanRetainOverlayAnchor` 比较的是**游戏客户区**尺寸，与覆盖层窗口大小无关 ⟹ 不受影响 |
| `SetWindowPos` 频率 | 只在矩形变化时调用（复用的 helper 本来就"未变不调"）；不用新增高频调用 |
| 非 16:9 / 窗口部分移出屏幕 | 矩形按客户区各自缩放并**裁剪在客户区内**；不越出游戏窗口 |
| 大地图路径 | **一处不动**（`mapVisible` 时回到整屏，与今天完全一致） |

## 7. 回归与验证计划

1. **重场景 A/B 复测**：在你报"掉帧 10–20 FPS"的场景（基线 26–60 fps）跑同样的 `A/B/A/B`，确认**相对**收益成立（本次绝对 +9.6 fps 属于 102 fps 的轻场景，不能外推）。
2. **D1 方案 A 的面积代价测量**：并集窗口（14%）下的 `A/B/A/B`。
3. **切换行为**：连续开关大地图 10 次，检查日志 `overlay-window-position-error` / `overlay-backbuffer-pending` / `minimap-overlay-drop` 均为 0，且肉眼无闪烁。
4. **DPI 100% / 125% / 150%**：marker 与状态栏位置、窗口位置逐档核对（未验证项）。
5. **任务书 §16 全量回归**，重点：3/4（完成态刷新）、6（大地图 marker）、9（切图后 Overlay）、11（DPI）、12/13（Alt-Tab/最小化）、14（穿透）、15（无残留 HWND）、16（设备重建后纹理索引重建）。
6. **长时间运行**：≥30 分钟，确认没有窗口尺寸漂移或内存增长（未验证项）。
