# 2026.9.27.2

- 程序更新现在真的会走 Mirror酱 了。此前即使填了 CDK，镜像的增量包也只是"下载了却没用上"——程序按区域打成的大包（分片）仍旧整包从 GitHub 重下。现在镜像提供的文件会和本机已有的文件一起计算，两者合起来覆盖的分片不再下载；同一次更新的实测流量从"镜像 86 MB + GitHub 84.6 MB"变成"全部走 Mirror酱，GitHub 0 字节"。
- 更新进度看得见了。更新卡片固定两行：「下载来源：Mirror酱（增量包）」和「正在进行：从 Mirror酱下载增量包 · 12.4 / 85.9 MB」，下面才是进度条；镜像下载、本机文件复用、最后校验都有真实进度，没有可计单位的阶段（等 Mirror酱 生成增量包、解压、原生自检）显示为滚动进度条，不再是一个停在 0% 的条。
- 连不上 GitHub 时也能完成更新：分片地址完全不可达时会自动改用 Mirror酱 的完整程序包（约 1 GB）继续这次更新。此前这种情况只能失败。镜像与本机都没有的单个文件仍然照旧走签名分片。
- 更新日志新增一行来源记录（`Logs/resource-updates.log`），会写明这次程序包来自哪里、以及镜像未能提供文件时的原因。
