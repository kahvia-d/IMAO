# 手绘路线编辑实施记录

分支：`codex/hand-route-editing`。规格以本次用户批准的完整计划为准。

## 任务

1. 编辑节点、有向连线、撤销及 v3 文件兼容。
2. 可见点位命中、拖拽、编号及双退格删除。
3. 手绘修改入口与原地保存、失败保留草稿。
4. 仅当前目标范围自动完成。
5. 合集顺序持久化与桌面拖拽。
6. 自动轮换、筛选联动、整体回归与独立审查。

## 约定

节点身份与编号分离；单前驱/单后继；重接替换冲突边；禁止自连接和环。
保存唯一至少两点的链及孤立点，多链不能保存。删除中间点自动接前后点。
双退格需两次独立按下，同一点，2 秒内；撤销保留 100 次。
只编辑手绘路线，编辑活动路线暂停；保存保留原 ID/合集/配置/存活点完成记录。
轮换仅由运行中的路线全部收集完成触发，按合集顺序向后，到末尾停止。

## 使用方式

- 2026-10-06 批量导出默认名：原实现固定为「路线-日期.json」。按玩家确认仍导出一个包，单条改为「路线名.json」，多条改为「首条路线名（N条路线）.json」；首条与数量使用排除损坏路线后的列表，未命名使用 ID，不含活动圆点。Windows 非法文件字符替换为下划线，移除末尾空格/句点并避免 CON/PRN/AUX/NUL/COM/LPT 设备名；用户选择的最终路径优先。全部损坏时先提示，不打开空导出的保存对话框。RoutePageRuntime 172 项通过，新增默认名回归先失败后通过，并覆盖多条、取消、未命名、非法字符、保留设备名及损坏项；原生导出格式与路线名称不变。

- 2026-10-06 底部插入与连续动画：末行带图标且被视口部分裁切时，插入边界不再隐藏，贴住可见底边显示。顺序变更通过原 ObservableCollection 增删/Move/按需更新，不重绑整份列表。WinUI Move 仍会重建移动项容器，因此先在原容器上同时滑动来源与补位行，等待 CompositionScopedBatch 的完成事件，再在同一 UI 回调提交顺序并清理位移；关闭默认容器进出场过渡，使用 StackPanel 保留所有行的真实高度以处理不同图标行高。来源临时抬高深度、使用不透明背景避免文字穿透。排序期间仅锁操作按钮，列表不随两次 IPC 请求进入禁用视觉。RoutePageRuntime 164 项通过，含原容器在动画中途保持、完成事件后提交、异步回包、最后图标行部分裁切；已查看实际合成器的前/中/后三帧与底部插入线截图。该轮替代之前「先提交后做过渡」方案，管理员实机操作仍待玩家复测。

- 2026-10-06 排序后闪烁：动画结束的状态渲染无条件替换 ItemsSource，导致路线行和选中视觉重新创建；普通导航状态推送也有相同问题。现在比较路线顺序及内容（类型图标数组按值比较），未变化时保留原集合、记录和容器；合集按钮同样避免重复创建。实际内容变化仍刷新，跨档案清除旧选择，批量模式保留原绑定刷新逻辑。新增回归先复现动画结束重建，修复后 RoutePageRuntime 155 项通过，包括新分配的 IPC 等价快照、动画期间最新提示、内容变化及档案隔离。实机动画观感仍需玩家复测。

游戏大地图路线列表：创建对应类型手绘路线，或先在列表选择手绘路线，再点击顶部「返回路线规划」右侧的「修改路线」。顶部修改按钮在未选择、普通路线、预览、损坏路线或已有草稿时禁用；每行不再放置修改按钮。空白处单击新增自由点，点击可见上游图标加入点位。按住节点拖到另一节点连接和修改方向；双退格移除悬停节点，Ctrl+Z 撤销最近编辑，Esc 留下待保存草稿。

保存需唯一至少两点的连接链；孤立点保留但不参与导航。修改活动路线时暂停，保存后用「继续导航」恢复。切换区域、画面失效和关闭地图取消未提交手势并保留已确认草稿。

桌面路线页单合集内拖拽路线行保存顺序；游戏路线列表勾选「自动轮换」后，仅收集完成会顺序前进，末尾停止。
