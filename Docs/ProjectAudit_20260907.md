# 全项目审计与基础修复（2026-09-07）

## 结论与范围

本次沿着“库街区公开数据 → 本地资源 → 坐标变换 → 截图 → 定位 → 点位/路线绘制 → WinUI 控制 → 用户数据保存 → 构建与发布”检查了项目。问题并不只在图像匹配：已确认坐标单位误判、可变容器跨线程访问、重复筛选、配置与用户文件保存、核心进程生命周期、截图资源管理，以及增量构建依赖识别等问题。

保留现有 C++ 核心与 WinUI 独立进程结构，优先重构这些边界，比直接重写全部识别算法更有依据。本轮没有更换检测器、降低几何验收门槛或添加当前位置特例，也没有覆盖工作区先前未提交的特征包和定位修复。

**这是一轮覆盖主要链路的源码审计和修复，不是“所有区域、楼层、显卡和分辨率均已验证”的结论。** 当前没有游戏进程可用于新的实机验收。对没有独立真值或缺失素材的项目，明确标为未验证。

## 已确认并修改的问题

### 1. 点位单位被位置数值改变（高优先级）

原 `KuroLocationToIdentifyCoordinate` 把 `stateId=8 / countryId=1 / max(abs(x),abs(y))≤10000` 的点位直接当成游戏坐标，其余点位才除以 100，并将该特例解释成黑海岸数据。

归档中的 `countryId=1` 对应瑝珑，黑海岸为 `900`。当前 31 个点位触发该特例，包括 `3200,1700`、`493,-4514` 等不同类别、不同位置的数据。官方前端统一除以 100，因此这 31 个点位在程序内被放大了 100 倍。阈值附近还会发生不连续跳变。

新增统一转换 `KuroPositionToGameCoordinates`，移除按位置猜单位的特例，并拒绝非有限坐标。测试覆盖小数值、负坐标、零点和跨越旧阈值的连续性。原始 JSON 和用户已保存点位 ID 不变。

### 2. 筛选容器重复、漏删与跨线程读写（高优先级）

- `AddItemDataFromJson` 每次都向容器追加；首页重新加载时再次启用相同类别会出现重复标记。
- `ClearItemData` 手工列出场景，漏掉 Fabricatorium，其他场景也只删第一份重复类别。
- IPC 线程修改类别列表时，定位/渲染线程直接遍历同一个 `vector`，存在迭代器失效风险。
- 小地图的近邻列表同时被更新、绘制和快捷键保存线程访问；大地图在加锁前先检查容器是否为空。

改为 `SceneItemStore` 按场景发布不可变快照：增加类别幂等，删除统一遍历所有场景，读者持有旧快照直到当前帧结束。近邻列表和显示设置补齐同步，避免通过局部加锁后仍暴露原始可变指针。测试覆盖八场景、旧快照保留与并发读写。

### 3. 筛选页用显示名称反查身份（中优先级）

原复选框回调通过翻译后的显示名反查 ID，同名物品或翻译变化可能操作错误类别。现在每个复选框直接保存并传递稳定 ID；保存失败时回退勾选状态并记录错误。

### 4. 本地配置保存不可靠（高优先级）

- `LocalSettingsService.InitializeAsync` 可被并发调用，后完成的初始化覆盖已修改状态。
- 多个异步保存任务共享可变字典，可能边序列化边修改、互相覆盖。
- `LocalItemFilter` 保存基于实例创建时的旧 JSON；不同页面实例可能覆盖彼此的修改。
- 原筛选文件写入程序目录，失败被直接吞掉；`JsonDocument` 反复替换也没有释放。

设置服务现在串行执行初始化与读写，使用独立字典副本提交，落盘成功后才更新内存。筛选操作每次在锁内读取当前文件并合并修改，改用用户数据目录，旧文件仅作为迁移来源并保留。损坏筛选文件不会被静默覆盖；普通设置 JSON 损坏时先保留 `.corrupt-*` 副本再使用默认值。

### 5. 用户数据可能被截断或保存在不可写目录（高优先级）

点位、路线和配置原来直接打开目标文件截断写入。写盘失败可导致文件损坏，部分 C++ 流默认不抛异常，内存却已经显示保存成功。已保存点位文件的更新时间也曾在锁外读取、锁内写入。

新增 C++ / C# 原子文件提交辅助：先完成同目录临时文件，成功后替换目标，失败保留旧文件。保存点位在提交成功后更新内存，避免重复保存同一 ID；加载先解析到临时 JSON 再发布。故障注入通过锁住目标文件验证旧内容得到保留。

用户数据统一放在 `%LOCALAPPDATA%/IMao-WinUI/` 下的 `SavedPoints`、`SavedRoutes` 和配置文件。首次运行复制旧程序目录中的数据，已有新目录文件优先，旧文件不删除；界面的“打开文件夹”同步指向新位置。**旧目录仅用于迁移，以后编辑或备份应使用新目录。**

路线追加时也确保先释放旧文件的读取句柄，再替换文件，避免 Windows 上二次保存被自身句柄阻止。

原子替换减少半写文件风险，不等同于多进程事务数据库或完整掉电恢复保证。多开实例同时编辑同一账户数据仍需后续设计。

### 6. 核心启动、重启、退出的生命周期竞态（高优先级）

原 `ShutdownAsync` 与启动没有共用生命周期锁；旧读取循环直接访问服务成员 `reader`，重启后可能读到新连接，或者用旧连接的退出事件覆盖新状态。连接取消、启动异常也可能遗留进程或管道。退出时界面同步等待进程退出，会阻塞 UI。

`CoreHostService` 重构为每进程独立会话，绑定管道、读取任务、取消令牌和待确认请求。启动、命令和关闭串行化，读取循环只接触所属会话，排队 UI 回调再次检查会话身份。关闭先取消并断开管道，再异步等待进程，必要时终止其自身子进程。

另移除了 `MainWindow` 构造期间对 `App.GetService` 的调用：窗口来自 `App` 静态初始化，此时 `Host` 尚未在实例构造中完成，形成服务初始化顺序风险。核心启动由页面加载后的服务入口承担。

### 7. 命令被拒绝但界面未处理，配置可部分生效（高优先级）

原界面不处理 `ack`，发送完成仅意味着写入管道。一个配置命令中，前几个合法字段可能已经生效，后面字段校验失败。

现在按请求 ID 等待确认，并显示拒绝原因到错误状态/诊断日志；命令存在有界等待。核心先验证配置命令全部字段，再逐项应用；输入错误不会把正在运行的核心误标为故障。重复启动不再把运行中的核心标成“等待游戏”，空闲时停止也不会永久停留在“正在停止”。

### 8. 管道背压可阻塞退出（高优先级）

原事件队列虽有上限，但写线程执行同步 `WriteFile`。客户端不读时，`Stop()` 的 `join()` 仍可永久等待。

读写改用重叠 I/O，写入超时会取消并等待 I/O 完成后回收缓冲，随后断开连接让主循环退出。首次连接等待也有时限。新增实际管道集成测试，客户端持续发送命令但不读取事件，检验核心能否正常结束。

### 9. 路线文件与路线线程（高优先级）

- 原批量读取的异常分支缺少返回值；格式错误还可能传播为不可预期结果。
- 路线名直接拼接文件路径，允许路径分隔符和 Windows 设备名。
- 路线列表与名称跨线程无锁；停止标志为普通 `bool`，并无条件 `join()`。
- 把 `(0,0)` 当作“尚无第一个点”，导致合法原点路线被丢弃。
- 录制使用玩家场景，而用户可以在大地图查看别的场景；还依赖当前筛选是否恰好有可见点位。

现在先完整校验文件和端点再发布路线，失败保留当前路线；验证文件名，快照访问列表，使用原子停止标志并检查线程可连接状态。录制从同一受锁保护的有效视口取得坐标与场景，离开地图/切换场景时清除半段状态，支持无筛选点位时录制。零点直接作为坐标处理。路线绘制还修正了左边界判断中把 x 错写为 y 的条件。

### 10. 截图与图形资源（中优先级）

- BitBlt 捕获原来未检查客户区获取成功/尺寸有效，失败时可能留下旧输出。
- 在位图仍被选入 DC 时调用 `GetDIBits`，并只检查返回值非零，没有要求取得全部扫描行。
- `SimpleCapture` 对已有所有权的 COM 返回指针调用 `copy_from`，增加引用后没有释放原引用；异常分支还缺少返回值。
- 截图与帧序号分别加锁读取，中间新帧到达时会给旧图配上新序号。

补齐捕获检查、清空失败输出、位图解除选择与完整行数验证；使用 `attach` 接管 COM 引用；图像与序号在同一临界区取得。真实设备丢失、显卡切换、HDR 和长时间捕获尚未实测。

### 11. 构建依赖前缀编码错配（高优先级）

当前机器仅安装中文 MSVC 消息资源。CMake 记录的 `/showIncludes` 前缀经过错误解码，与编译器实际字节不同，Ninja 无法可靠登记头文件依赖；日志大量包含本应被 Ninja 消费的依赖行。单纯设置 `VSLANG=1033` 或切换控制台代码页在本机未解决问题。

新增原始字节探测与小型原生编译包装器，只把实际依赖前缀转换为固定 ASCII 标记，保留编译参数和退出码。真实项目还揭示 `/source-charset:utf-8` 会让输出从系统编码变成 UTF-8，包装器同时处理这两种形式。`Test-MsvcDependencies.ps1` 使用两个真实编译目标验证两种编码，均记录 `probe.h`，修改头文件后均重新编译与链接。真实主程序的 `App.cpp.obj` 也已核实记录 351 项头文件依赖，包含 `App.h`，证据见 `out/system-audit/core-dependencies.txt`。关闭本项目没有使用的 C++ module 扫描；资源编译显式依赖资源目录与 `resource.h`，避免绕过包装器的旧资源依赖扫描。构建默认两路并行，减少内存压力。

### 12. 二次开发版本仍提示安装废弃上游版本（中优先级）

首页原来比较硬编码版本与原上游 Releases，可能把当前二次开发版本引导回旧版。移除自动检查调用。在没有明确当前发行仓库之前，不编造新的下载入口。筛选重构后也移除已无调用的 ServiceStack 包依赖。

### 13. 回归工具可能虚报通过（高优先级）

小地图回放只累计缺图数量，没有将缺图纳入最终验收；无标注样本的精度还默认取 1。现在最终验收要求素材完整、实际处理至少一个样本且存在标注真值；大小地图的公共入口拒绝空样本清单。保留原有准确率与延迟门槛。

测试脚本另统一托管程序集的输出和执行目录，避免开发环境的 `Platform=x64` 导致构建新程序集却运行旧文件。
