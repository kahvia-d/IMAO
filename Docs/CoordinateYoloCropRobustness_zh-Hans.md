# 坐标 YOLO 裁剪鲁棒性

研究分支 `research/yolo-crop-robustness`，起点为 2026-11-06 核实的 `main` 提交 `5b5601a`。应用入口从 `Assets/models/coordinate-yolo/` 加载一份 ONNX，CPU、DirectML 共用。本轮训练和回放均使用本机保留资料，路径清单见[前期素材保留说明](CoordinateYoloResume_zh-Hans.md)。

## 修复目标与取舍

只要截图保留了完整、可辨认的 XY，移动裁框或改变字高后仍应读出同一对带符号整数。裁掉首位或负号时允许拒识。计分分别记录整对 XY 正确、错误和拒识，避免用降低置信度门槛换取表面上的读出率。

本地四段有效采集共 3,197 张坐标原始条图（1,160、1,162、440、435），不重复计小地图、对比度副本及增强图。训练来源、故障集与历史清单有交集，不能把这些数量相加充当独立验证样本。

建议沿用自训权重，以真实几何增强续训为主，同时修正输入采样和符号解码。半透明合成保留为独立实验组。先在真实游戏背景叠加字形和描边，再对整幅图裁剪、缩放和降采样；字符框同步变换。按采集会话分配训练与验证，留出会话也禁止用作背景。重点补充明亮草地、低对比度、正负号组合、重复数字、无坐标画面及边缘切掉字符的例子。信息不足的裁图单列评估拒识。

## 后续训练与交付方案

1. **冻结对照。** 以原 flight、当前几何增强权重和完整分支识别器为三个基线。按原始采集会话或录像划分数据，再派生裁图。每项保留同源帧的原位、偏移和缩放版本，单独统计独立来源数与派生测试次数。
2. **建立半透明合成组。** 从训练侧截图提取真实游戏字形、描边和间距，在无坐标的游戏背景上先合成完整坐标行，再对整图执行裁剪、缩放、降采样及压缩。覆盖暗地面、明亮草地、纹理与字形相近的背景；分别改变字高、裁框中心和宽高。记录生成参数、完整字符串、字符框和字符可见比例。完整可读、无坐标、符号或首位残缺三类分开。残缺负数不能作为正数真值。
3. **比较训练配方。** 固定训练来源、训练预算、原生解码器和评测清单，比较真实几何增强与增加合成样本的候选。先分别加入透明度、背景、裁剪因素，再验证组合，定位增益来自哪一项。用训练侧开发集选择配方，已参与调参的故障帧只作回归。最后用新录像进行一次盲测。
4. **验收整对带符号 XY。** 原位、各方向偏移、缩放、组合扰动、真实正 X、淡负号和无坐标分别报告正确、错读、拒识。候选须在真实困难画面上提高正确数，保持正常裁框正确数，且各组已知错读和无坐标误报均不增加。重点复核历史两项分歧。低清组单列，持续回放另报 CPU、DirectML 的 P95 及超过 100 ms 的帧数。
5. **现场与交付。** 在开发测试客户端采集真实失败画面，把同一帧交给旧版与候选回放。核对带符号 XY、拒识和现场延迟后，将 ONNX、配套 model.json 和原生识别器作为同一版本交付。

## 权重与识别流程

几何增强使用 flight 的 164 个自有来源。每个有字来源保留原样本，并从更大的真实截图生成三种新的裁剪和采样，各产生原图、对比度图。标注随原图变换。原始 328 对图像与标签逐项核对 flight v2 协议摘要。候选从 flight 继续训练 16 轮，以最后一轮参数占 70%、原 flight 参数占 30% 插值，导出一个固定输入 `[1,3,64,896]` 的 ONNX。实验比较了只续训、半透明文字合成、真实游戏字形合成及从通用 YOLO11n 起训。半透明合成组在放大裁框 10% 时有 73/77 正确，但在正确裁框中产生 3 个错误。分支模型采用真实裁剪增强权重。

原生预处理和解码是完整修复的一部分。识别器从当前截图中拟合多个字形共同支持的行高与顶部位置。浅色背景上还可以使用单独从真实亮背景中提取的字形模板。几何匹配原训练布局时可直接采用原图、对比度双路确认的结果；其余情况在估计的文字行上重新采样，要求两个采样位置读出相同 XY。模板及版本随 `model.json` 交付。诊断采集保留原裁图、采样参数及各路检测框，可离线复算。

如果两路都在裁图左边缘看到了数字，图外可能还有符号，系统会拒绝有歧义的正 X。还有两类来自实际回放的约束：重复数字之间的弱重叠框需要两侧更强的同字符框才能消除；逗号与正 Y 的首个数字之间若有明显缺字间隙则拒识。训练原标注中，无符号间隙约为 0.003 个数字宽，负号占用 0.67 至 0.81 个数字宽。Z 只在相符的证据支持时输出。

已知故障会话共有 78 帧，其中 77 帧能人工确定 XY，另 1 帧遮挡。下表数字依次为正确、错误、拒识。每行对照使用完全相同的源帧。

|---|---:|---:|
| 正确裁框 | 75 / 0 / 2 | 76 / 0 / 1 |
| 向右、向下各 1 px | 0 / 0 / 77 | 75 / 0 / 2 |
| 居中放大裁框 10% | 0 / 0 / 77 | 76 / 0 / 1 |

八个方向的 1 px 偏移分别得到 75 至 76 个正确 XY，错误均为零。保留左边距、裁框大小从 85% 到 115% 的四组对照，分别为 76、76、75、73 个正确 XY，错误均为零。

把两项改动拆开，在同一组右下各 1 px 的输入上，新 ONNX 加原图/对比度基础解码得到 64 正确、1 错误、12 拒识（`native-evaluation/geometry-blend70-boundary-score.json`）。加入文字行定位和多次采样确认后为 75 正确、0 错误、2 拒识。单独复制 ONNX 到其他识别器只能获得其中的权重改进。

448C5F2E 整段 440 帧在本轮隔离，未作训练图或合成背景。按固定步长读图转录 44 帧，38 帧可判读、6 帧待定。首次盲测中，相比旧版，左上偏移从 2 正确、12 错误提升至 38 正确；另两种偏移在同一帧漏了 Y 负号。这个会话随后转作回归验证。补充逗号间隙检查后，六个有完整捕获像素的平移/原位条件各正确 37 至 38 帧，错误均为零；符号被居中缩框裁掉的 38 帧全部拒识。

另一次独立复核采用 10 月 23 日较早会话的 41 张完整 WGC 画面。该会话录制未完整结束，3 张稀疏回读已排除。40 张无坐标画面均无误报；唯一一张可读坐标为 `(-722,1306)`，正确裁框、八个方向偏移及两种缩放共 11 次均正确。旧 flight 在这 11 次中正确 6、错误 3、拒识 2。这组只含一处真实坐标。

## 合入前的工作与验收

同一台机器对相同的 96 个裁图分别运行旧、新模型及配套识别流程。每次剔除首帧，其余 95 帧按原生识别耗时统计，不含 PNG 解码。CPU 的中位数/P95 由 9.9/12.4 ms 增至 48.6/228.3 ms，DirectML 由 3.4/4.6 ms 增至 38.7/181.3 ms。单次离线回放的尾部耗时已超过桌面活跃读取的 100 ms 提交间隔。

1. 最慢的帧集中在没有坐标的画面。改为最多四组并行搜索不同字高，按字高顺序归并以保留相等分数的取舍。原图及增强检测框都为空，并且两个字体外观组在预期高度的匹配均低于 0.50 时，可直接拒识。相同 96 帧三次顺序回放中，候选 CPU P95 为 55.9–57.9 ms，DirectML 为 36.2–55.5 ms。只作并行而保留无条件全搜索时，CPU 三次 P95 为 127.9–138.3 ms。
2. 在单帧原图、增强图中分别取置信度至少 0.85 的数字。每路至少六个数字、至少四分之三同意字顶和字高、两路结果相符、且字高接近训练尺度时，用这个范围约束模板搜索。仍由像素模板定位文字。未校准裁图若原始双路读不出完整 XY，则保留全范围搜索，避免裁切的数字框低估行高。验收线为故障集八方向各至少 75/77 正确且零错报，正常裁框至少 76/77，裁掉负号的 77 帧全部拒识，历史 274 个无坐标输入零误报。两条标签争议由人工判读原图，保留旧版评分。
3. 四段独立录像的几何盲测见上文。另在 17:21 的第五段实机录像按 10 Hz 抽取连续 477 帧，原生 CPU、DirectML 的 XY 逐帧一致，在修复下文的淡负号问题前，403 帧有读数、74 帧拒识。推理前固定间隔单独转录的 12 帧均正确，其余帧未逐帧转录。低清云串流单独计分。实际游戏进程的开发客户端连续读取仍待现场验证。

四段录像又补测了位移与缩放同时发生的情况。在原图有完整像素的三组组合中（缩小 15% 并左移 3、上移 2 px；缩小 15% 并右移 3、下移 2 px；放大 15% 并左移 3、上移 2 px），候选分别正确 17、18、17/19，合计 52 正确、5 拒识、0 错读。旧版合计 7 正确、49 拒识、1 错读。放大 15% 同时下移 2 px 的条件会越过原画面底部，已排除。

性能优化阶段的回放结果在 `accepted-*.json`。固定的几何、缩放、隔离会话和历史集共 3,490 次输入，该阶段优化前后逐帧 XY 一致。96 帧混合基准的 CPU / DirectML P95 分别为 55.1 / 36.6 ms。第五段录像连续满负荷回放时为 97.4 / 31.2 ms；按桌面 100 ms 周期间隔送入相同的 477 帧时为 128.5 / 107.7 ms（去掉首帧后分别有 44 / 26 帧超过一个周期）。这是识别器耗时，不包括抓屏和地图更新。短基准达标，连续节拍仍有尾部延迟。

## 淡负号与真正的正坐标

第五段录像还有七帧 X 负号很淡或处在画面撕裂处。原始截图及相邻录像帧用于人工复核，程序逐帧判断。早期候选在这七帧的原位及八方向偏移共 63 次中错报正 X 达 62 次。将当前画面的数字间距作为尺度，区分原生文字布局与额外留白，再把采样平移量扣除后检查首位间距。错报符号的 62 次改为拒识，另 1 次正确。真正的正 X 对照使用六个来源，每帧测试原位和三种居中放大，相应的 24 次读数由 19 正确、3 错读、2 拒识变为 21 正确、0 错读、3 拒识。对照集还暴露了弱数字框覆盖逗号、不同采样在同一位置混淆 3 和 6 的错误。解码时检查数字与逗号的重叠，并要求新采样提供足以推翻原始双路竞争读数的字符证据。这组是发现问题后固定的回归集。

第五段连续录像复测时，477 帧有 396 帧返回 XY，81 帧拒识。此前误报的七个正 X 全部改为拒识，固定转录的 12 帧均正确。CPU 与 DirectML 在这 477 帧上的 XY 和 Z 逐帧一致。冻结历史集中评分的正确、错误、拒识及无坐标数均与表中一致；22 个未定项各有 11 个返回和拒识。其余连续帧未经逐个字符的人工判读。

最终原生核验记录在 `prefix-*.json`。当原图缺乏完整分隔符，或原图解码失败且没有可通过另一采样消歧的竞争数字框时，额外采样可以跳过一次对比度推理。六组共 3,913 次输入的完整选读结果与优化前逐项一致。96 帧混合集去掉首帧后，CPU / DirectML 的 P95 为 41.7 / 23.4 ms。以 100 ms 周期提交第五段录像的 477 帧，两种后端的 XY、Z 逐帧一致；去掉首帧后，识别耗时 P95 为 86.7 / 75.2 ms，分别有 15 / 6 帧超过 100 ms。以上均为本机离线识别耗时，现场抓屏到地图更新的端到端延迟仍待测量。

## 发布前恢复链路回归

2026-11-11 补充了 Pocket 文档指出的 PC 恢复问题。全局请求没有有效提示时版本为 0，防止空 OCR 提示重置跨请求搜索覆盖；楼层范围留在单次请求中，完整失败范围在当前采集会话与 UI 世代内撤销。范围首次超时后先保留两秒连续全局搜索机会，再允许重试；同范围反复超时时等待倍增（最多约 34 分钟），避免以固定短间隔不断打断全局覆盖；有足够几何支持的全局候选获得原有两秒独立帧确认窗口。请求日志使用实际提交版本，迟到结果不能清空较新 OCR 提示。新增 VisualRecoveryHintsTests 验证这些调度条件，原有几何质量、独立新帧、时效和取消门槛继续在生产调用链检查。同步界面把待上传说明改为点位状态变更，覆盖完成与取消两种方向。

## 复现入口

1. 在仓库根目录先执行 `. .\scripts\Enter-DevEnvironment.ps1`。训练解释器为 `out/coordinate-yolo-selftrain-20261015/.gpu-venv/Scripts/python.exe`。下列脚本均位于 `tools/coordinate-ocr/robustness/`。
2. 在新研究输出目录（可用 `IMAO_COORDINATE_RESEARCH_OUT` 指定）运行 `train.py geometry`，之后运行 `blend.py geometry .7`。比较组可用 `train.py control`、`train.py mixed`、`train.py mixed --initial official`。数据集随本地保留树读取；训练和评测严格分开。
3. 运行 `freeze.py`、`scale.py`、`holdout.py` 生成各套原裁图与真值清单。以 `scripts/Build-CoordinateYolo.ps1 -DependencyRoot . -BuildDirectory <研究输出>/final-native` 构建仓库原生回放器。历史清单由 `evaluate.historical_manifest()` 读取冻结的 `truth-reviewed-v1.json` 和磁盘上保留的原图与对比度图。
4. 运行 `product.py geometry-blend70 --build final grid scale historical holdout`。打包出的模型目录可直接用于原生回放器的 `recognize` 模式。每帧结果、耗时、分类计数写入研究输出目录的 `final/`。纯检测器对照用 `infer`；实机记录的多位置结果可用 `decode` 原样复算。
5. 本机当前证据位于 `out/coordinate-robustness-v1/`。保留 `final/` 的结果、`native-evaluation/source-lock.json`、各训练集的清单和最后一轮权重、`session1-holdout/` 的独立复核及 `shift-replayed/` 的原生诊断一致性回放。
6. 四段录像的转录见 `video-holdout.csv`。用 `video_holdout.py <本机 NVIDIA 录像根目录>` 生成 `video-holdout/manifest.json`。在同一清单上分别运行旧、新模型的原生 `recognize`。名称以 `combined-` 开头的组额外叠加位移和缩放，单独计分。
7. 用 `video_holdout.py --score <原生报告>` 对照录像转录计分。`video_holdout.py --continuous <录像路径>` 从 1440p 原片按 10 Hz 抽取连续裁图到 `video-continuous/`。连续回放使用同日 `Desktop 2026.10.18 - 17.21.09.02.mp4`。原生 `recognize` 测连续满负荷吞吐，`recognize-paced` 按桌面提交周期送帧。清单行加 `"profile": true` 可额外记录文字行定位耗时和补采样次数。
8. `video_holdout.py --sign-regression <录像根目录>` 重建 87 个符号专项输入，再用同一开关及 `--score <原生报告>` 计分。连续录像中发现的七帧按顺序解码，复核每个原位裁图的像素 SHA-256。按视频帧号随机跳转在这段录像的两处会取到邻帧。
