“加入当前视野”按完整游戏客户区内、当前筛选且未完成的点追加，包含底部工具台后方的点；工具台展开、收起不改变这个范围或“视野外”计数。点击、框选、套索及 RB 光标选点仍遵循工具台遮挡规则。已选点会去重，撤销恢复本次追加前的选择；真正位于屏外的点不加入。

后续键位更正：按用户纠正，大世界组合键现为 **LB+B 完成、LB+X 附近攻略**；旧 RB+B/RB+X 不再触发，大地图 LB 工具台／RB 独立助手保持原位。更正后托管回归 508 项通过（含 8 条旧组合失效断言），标准构建 0 错误、资源与页面元数据检查通过；本次日志位于 `out/lb-shortcuts-20260908/`，更正前的历史验收日志保留不覆盖。用户提供的游戏设置截图中 LB+X 同时绑定切换瞄准，本项目不拦截游戏手柄输入，其原生动作可能同时触发，需实机确认。

## 功能与键位

游戏大地图内，**点按 LB 打开底部地图工具台，点按 RB 打开独立点位助手**，均在松开时执行。入口需要确认游戏前台和有效的大地图上下文。手柄体验开关关闭时不处理这些动作。

地图工具台提供“路径自动规划”和“点位筛选”两个入口。路线页复用现有选点、矩形框选、套索、指定起点、生成预览、开始指引、暂停、跳过和重新规划等操作；筛选页与主界面使用同一份筛选状态和同一控件。工具台本身支持鼠标操作，不要求持续连接手柄。

大地图手柄标记完成：将游戏白色光标圈对准标记 → RB 打开独立点位助手 → 左摇杆／方向键选中一个点 → A 打开详情 → 按住 X 约 0.6 秒。列表优先显示光标圈内的未完成标记；重叠组逐个列出，只完成明确选中的点。当前路线目标与开图前位置附近的点作为独立备选，和光标列表去重。圈内点不受大世界附近距离限制；框选、套索仍仅用于路线选点。

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| 工具台 | 方向键／左摇杆、A | 移动选择、确认当前操作 |
| 工具台 | B | 先关闭控件内展开内容或取消未提交绘制，再返回上级；根层收起并返回游戏 |
| 矩形框选／套索 | 左摇杆、按住 A 后松开 | 移动光标、绘制并提交选区；只选择路线点位，不批量完成点位 |
| 筛选 | 方向键／左摇杆、A | 浏览分类和勾选；搜索文字使用键盘，不提供屏幕键盘 |
| 普通探索 | 先按 LB，再按 B | 全部松开后，尝试完成附近点 |
| 普通探索 | 先按 LB，再按 X | 全部松开后，打开附近点攻略 |
| 附近完成选择列表 | A | 完成当前明确选中的一个点，不先打开攻略 |
| 附近攻略选择列表／独立助手 | A | 打开所选点攻略 |
| 攻略 | LB／RB、右摇杆、A、B | 翻图、滚动、放大图片、返回；放大后右摇杆平移图片 |
| 攻略详情 | 按住 X 0.6 秒 | 只完成当前展示的明确点，保存成功后结束本次完成操作 |

探索组合允许 LB 与 B／X 在同一次采样中同时按下；先按 B／X 再补 LB 不触发。组合必须全释放后才执行一次，移动和转镜头的摇杆轴可以保持偏转。其他按钮、扳机干扰、组合中途换键、断连、上下文切换或采样中断会取消手势，并要求重新释放。**旧 L3 单击及 L3+LB 不再触发本项目探索动作。**

## 附近范围与明确点位

键盘附近完成快捷键（默认 Z）和 LB+B 共用规则：有效小地图中的当前筛选、未完成点，点位到玩家的投影距离必须 **小于 15 像素**。这是从原 10 像素扩大 50%；路线自动重排原有的 10 像素判断不随之改变。

- 没有候选时显示可见提示，不静默成功。
- 有多个完成候选时始终先展示列表，A 只提交高亮的一个点。
- 只有一个候选时，在操作锁内重新读取最新可信位置与候选。仍然唯一且身份相同才写入；出现第二个点、原点离开范围或定位过期时提示重试，不换成另一个点。

LB+X **只查询附近点，不优先路线目标，也不回退到路线目标**。候选必须是当前筛选中的未完成点，位于实际小地图范围内，并且与玩家的地图坐标距离不超过 **120 地图坐标单位**。攻略搜索不使用 15 像素完成圈，因此可以查看较远但仍在当前小地图内的点。一个候选直接打开攻略，多个候选先选择。这里的像素和地图单位都不是米数或高度。

附近探索动作使用最新可信小地图位置，不使用打开大地图前冻结的玩家坐标。大地图独立助手仍有其原有快照列表语义，不能把那份列表当作当前探索位置。“当前目标攻略”工具台按钮和键盘原路线攻略入口继续使用明确的路线目标，与 LB+X 的附近攻略分开。

## 定位、提交与窗口边界

附近候选列表的阅读时间与定位观测的新鲜度分别管理。已登记的选择列表／攻略窗口在前台时，允许现有定位链继续观察游戏；不会因为列表打开数秒便必然过期，也不会把窗口登记当成可信位置。提交仍需要最新可用定位，并重新核对点位身份、候选修订、配置档、场景、筛选版本、完成状态、距离和窗口登记会话。重复的同一点提交返回既有结果，不重复保存或继续完成下一个点。

新的探索快捷动作只在游戏实际前台触发。浮窗必须取得前台并通过可见性检查后才接管操作；进入、返回、重连与上下文变化均有释放屏障。异步打开、登记和返回请求按会话核验，迟到回复不能复活旧窗口或抢回用户已经切走的焦点。

返回游戏核对原窗口及进程身份，并确认实际前台结果。失败时保留可重试状态，松开后按 B 重试，或直接点击游戏；不连续自动抢焦点。工具台向攻略交接时，源窗口保持到目标交接完成，不用固定等待时长猜测成功。

断开手柄不应结束正在进行的纯鼠标工具台操作；若本次未提交绘制由实际手柄操作接管，断连则取消该手势。地图、筛选、场景、窗口或会话变化会取消失效的未提交输入。已确认的路线选点和点位完成记录遵循各自原有保存规则。

这些是本项目对动作与窗口的约束，并不证明游戏一定忽略后台手柄输入。不同游戏状态和输入后端仍需实机检查；测试窗口通过也不代表真实游戏组合键没有冲突。

## 2026-09-25 修正：路径自动规划页“左摇杆不能右推”

实机现象：重启 IMAO 后路线仍在导航中时，在大地图打开工具台并进入路径自动规划页，左摇杆只能上下，右推没有任何反应。

根因不在输入层，而在选中项的身份：`route` 页在“选点草稿为空、仍有活动路线”时有两个按钮共用同一个指令键 `new`（「开始选点」与「新建路线」）。窗口原来用指令键当身份，而每次读取手柄输入、每次刷新高亮都会重建导航表，再按 `Tag` 找回选中项，于是永远命中第一个同名按钮。右推其实已经把选中项移到了第二个按钮（日志里 `geometricNeighbour=True`、偏移 111 像素），紧接着的重建又把它拉回第一个，界面上纹丝不动。2026-09-25 16:02 的 `map-tools-direction` 记录连续八次右推全部写成 `from='new' to='new'`，就是“移过去又被拉回来”的外观。

修正：

- 新增 `IMao-WinUI/Models/GamepadNavigationList.cs`（纯模型，可单测）。选中身份改为“哪一个控件”（引用身份，天然唯一）；控件被重建时退回指令键，但只在该键于当前列表里唯一时才可信；两者都不成立则保持位置。`MapToolsWindow` 的导航表、方向选择与高亮全部改走它。
- `map-tools-direction` 诊断补上 `index=` 与 `label=`。只记指令键会把“移过去了”和“没动”写成同一行，这正是本次误判的由来。
- 两个按钮动作相同（都发 `new`）是既有界面设计，本次不改；改动只保证它们都能被选中，也不影响上下与左推。

验证：新增 `Tests/ManagedRuntime/GamepadNavigationListTests.cs`（14 项），几何偏移取自实机日志，方向选择走生产代码 `GamepadDirectionSelection`。把旧算法临时放回模型时，该用例在第一条断言即失败（选中项被拉回第一个同名按钮）；改回本次实现后托管 **669 项全部通过**，生产构建 0 错误。**尚未在真实游戏与实体手柄上复验。**
