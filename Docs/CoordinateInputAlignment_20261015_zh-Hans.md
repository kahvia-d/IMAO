# 坐标 OCR 实际输入、导出与日期边界诊断

本轮按用户确认先暂停继续微调，核对相同图片、相同权重的训练 checkpoint 与原生导出模型。没有新训练、下载、生产修改或模型替换。结论是：检查范围内没有发现导出计算错误；确认了短裁片与整条读数的输入差异，并将识别文本和解析后的结果分别计数。尚未得到可采用的新模型，也没有证明所有退步只有一个原因。

## 检查方法与范围

本地证据目录：`C:\Dcode\WWMAP-TOOLS\out\coordinate-input-alignment-20261015`。

独立 C++ 探针调用现有 `ppocr.lib` 的 `CRNNRecognizer::Run`，参数与既有离线回放一致：CPU、4 线程、MKLDNN、batch=1、基础尺寸 3×48×320。仅在诊断构建生成的头文件副本中开放 predictor 成员访问，读取 Run 后实际 feed/output；没有改生产头文件、静态库或旧回放程序。对输入张量逐像素独立重建，防止把外围 PNG 当作内部输入，或误读被执行过程修改的 feed。

选取训练来源 744、748、884、896，覆盖清晰与草地遮挡。每帧 contrast / tophat 两路，各取训练用标签辅助短裁片与实际原生预处理的固定整条 ROI，共 16 张 PNG。初始化与 v3 预处理配对模型分别检查这 16 张；v4 上下文模型另检查 8 张整条 PNG。所有直接拟合检查都是训练来源诊断，不能当作留出集或独立会话准确率。探针输入清单没有标签。

Python 侧使用既有 Paddle CPU 3.0 环境、原官方模型架构及对应 checkpoint，直接接收探针落盘的浮点张量，比较 softmax 输出和完整 CTC 文本。另以已固定的训练 `RecResizeImg` 处理同一 PNG，观察训练输入的结果。额外使用一张有明显 B/G/R 差别的合成条纹检查通道顺序，不用于准确率。

## 同张量计算与预处理

| 检查 | 结果 |
|---|---|
| 初始化 / v3，同实际张量的原生与 checkpoint 文本 | 32 / 32 完全相同 |
| 上述 softmax 最大绝对差 | 0.00006938 |
| v4，同实际张量文本 | 8 / 8 完全相同 |
| v4 softmax 最大绝对差 | 0.00001079 |
| 全部实际输入，包括合成色条，逐像素重建 | 41 / 41，通过；最大差 0.0000001193 |
| 探针与既有 v3 / v4 原生整条回放文本 | 16 / 16 完全相同，置信度差小于 0.00001 |

检查到的实际输入是 BGR、NCHW、像素缩放到 [-1,1]。高度均为 48；短图右侧先以 uint8 的 128 补到至少 320 宽，归一化后 padding 为约 0.003921628。训练 `RecResizeImg` 在归一化后补浮点 0，固定到 384 宽；其归一化补零不等同于原生的像素 128。

892 宽整条 PNG 在原生中保持 892 宽。旧 v3 的 384 预处理若接收同一整条图，则将其压缩到 384；但 v3 实际训练的是坐标短裁片，不能据此声称它训练时曾把这些整条图压缩。真实差异同时包括取景内容、日期上下文和几何。v4 的整条上下文训练宽度为 896，更接近原生 892，其失败不能统一归因于 384 压缩。

对 v3 的 8 张短裁片做两个控制：保留实际内容，只将 padding 改为浮点 0；再把补零宽度从 320 改为 384。8 张均保持相同识别文本。这个小样本不支持“只改 padding 就能救回前轮结果”，但也不能排除边缘案例对 padding 敏感。

## 原始文本与已有解析的分解

从既有原始回放重计相同 170 张开发 XYZ，以及另外 27 张训练配对来源。这里只分析 contrast-clock 单路线；没有改解析、阈值、互证逻辑或标签。

“原始三元组正确”要求文本从开头就能按现有符号和逗号读出完整 XYZ，第三个整数不能与后续数字粘连。额外记录“已知 XYZ 字面前缀后紧接 2026- 日期”的歧义情况，它需要标签才能知道理想切分，绝不当作安全返回或识别正确。

| 模型，同 170 张开发图 | 原始三元组正确 | 其中最后未返回 | 高度与日期粘连（另计） | 最终正确 / 错误 / 未返回 |
|---|---:|---:|---:|---|
| 数字初始化 | 163 | 0 | 1 | 163 / 4 / 3 |
| v2 正 X 补训 | 163 | 2 | 1 | 161 / 1 / 8 |
| v3 彩色配对 | 163 | 3 | 1 | 160 / 1 / 9 |
| v3 预处理配对 | 147 | 19 | 17 | 128 / 1 / 41 |
| v4 上下文 | 32 | 0 | 0 | 32 / 6 / 132 |

v3 预处理配对的 19 次“原始三元组正确但未返回”，分数均达到既有 0.65 门槛。另 17 次日期粘连属于有歧义的字符串，不能算成单纯的数字读错，也不能擅自从数字串拆出高度。当前边界处理未验证完整日期时钟时会回到原解析路径，本表不表示所有未返回均来自某条专门拒绝规则。

例如 748 原文为 `-557,-37,-25-2026-10-1414-10:23+8-`：坐标部分正确，但日期时钟与分隔错误使完整文本没有安全返回。139 的 `-507,1971,512026-10-1414:05:09-+8` 则无法仅凭数字串确定 Z 与日期的切分。

27 张已训练配对来源中，v3 彩色配对原始三元组正确 23，最终正确 19；v3 预处理配对原始三元组正确 24，最终正确 12。短裁片拟合改善并不等于整条固定 ROI 可用性改善。

v4 原始三元组本身只有 32 / 170 正确，不是仅被日期门禁挡住。它在本轮训练来源小样本中仍出现多余负号，例如清晰 884 原生与 checkpoint 都输出开头 `--464,-109,17`。其 27 张训练配对来源也仅原始三元组正确 10，最终正确 9。不能将此模型靠放宽边界包装成有效改进。历史留出草地 780 的 X 负号误识别问题仍未修好。
