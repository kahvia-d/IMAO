# 短时完整诊断复现采集

用户已于 2026-10-23 确认：提供几分钟的完整复现模式，用玩家实际采集的数据和画面还原故障；实现后刷新开发测试树实测。

## 设计

- 默认 180 秒，可手动停止。录制、排空写入、完成、不完整失败的状态均显示在诊断页，结束后可打开本次目录。
- 保存实际被程序消费的 WGC 帧，而非另开录屏或强制改变局部回读策略。局部回读帧携带实际有效矩形，空白区不能被当成游戏画面。
- 客户端裁剪保存原始帧引用和精确矩形，按相同像素还原，避免重复编码全屏图。小地图原图、归一化图、掩码、SURF 输入，以及 OCR 原图、原始/增强路线和字符检测结果单独留存。
- `captureRun + frameId` 区分探索进程内的采集；`sourceSequence` 关联 WGC 交付；`requestId`、原始帧号关联异步识别。日志在对应线程作用域中携带这些字段；异步结果消费仍引用结果自己的原始帧，不能冒充当前帧。
- 全部结构化日志进入同一诊断记录流；没有画面上下文的后台日志明确保留为空，不强行挂到最新截图。
- 后台无损写入：WGC 大帧使用系统 XPRESS 分块压缩，其他裁剪为 PNG。队列预算 256 MiB、会话磁盘上限 64 GiB；达到时停止接收，排空已接收记录，并明确标记不完整及原因。普通关闭/自动到时排空后完成。开始新会话不沿用旧限流或图片计数。
- 包含版本、资源快照、模型哈希、原始输入、预处理与检测信息及完成清单。分析工具检查关联、还原客户端，并导出原生 YOLO 回放清单；运行识别仍需匹配的模型与对应资源。

## 方案取舍

采用短时完整证据目录。继续旧的两秒采样会遗漏故障；仅录视频无法证明程序实际输入；独立全帧捕获会改变原故障路径。相同帧由多条日志引用，不按日志行重复编码。

诊断不顺带修正窗口裁剪、负号策略或定位门槛，以便采到目前真实行为。界面使用玩家能理解的状态，不暴露内部编号。

## 实测

在诊断页开始采集，切换窗口/全屏与分辨率，复现 SURF/OCR 异常，提前停止或等待结束，将整个会话文件夹用于离线核对。采集有开销，空间不足或写入跟不上必须被识别为不完整，不得宣称完整复现。

## 验证与交付（2026-10-23）

- 真 WinUI 自包含构建和 publish 成功；原生 ReproCaptureTests 与坐标异步运行时回归通过，离线检查器 15 项测试通过。
- 实际 4K BGRA 输入按 80 ms 间隔写入 120 帧，120/120 保存、遗漏 0；约 2.75 GB。无损采集磁盘占用较大，实际负载随画面和磁盘性能变化。
- 真实画面录制夹具 → 客户端裁剪还原 → 模型哈希检查 → 原生 OCR 回放：8 条记录、1 个识别请求、0 错误，得到 (-715,1325)，Z=42。
- 修正刷新脚本的时间戳捷径：同大小但内容不同的旧文件必须按 SHA256 更新；BinaryRoot 仅切换二进制来源，资源仍从标准构建树核验。
- 通过刷新脚本先同步原生构建树，再同步托管 publish；375 个顶层文件逐一核对 differing=0，自包含及发布 resources.pri 一致。测试客户端完全退出后已重新启动，WinUI 与 CoreHost 存活；游戏内复现验证待用户进行。
- 证据目录：`out/evidence/repro-capture-20261023/`。采集输出位于当前用户 `%LOCALAPPDATA%/IMao-WinUI/Diagnostics/repro-*`，诊断页可直接打开。
- 记录的是程序实际收到和使用的 WGC 输入；当前若为局部回读，只有 validRegions 内像素有效，不代表额外录制了一份完整桌面视频。无画面上下文的后台日志保留为空。
