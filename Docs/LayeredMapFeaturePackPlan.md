# 分层地图特征包落地方案（草案，2026-09-22）

依据：`Docs/LayeredMapFeatureMeasurement_20260922.md` 第七、八节（分层瓦片是 RGBA 叠加层；
实机合成 = 地表底片 × 0.20 + 当前层；小地图 = 底片 + 当前层，无其他层遮罩）。

## 零、离线 A/B 结论（2026-09-22 深夜，已验证）

用发布包同款 builder 对同一个今州瓦片归档建了 4 个包，再用三种查询去锁定
（`scripts/Test-LayeredTileComposite.ps1`，产物在 `out/map-regions/ab/`）：

| 包 | 关键点 | 真机地表小地图 | 洞窟查询（合成图裁片） | 洞窟查询（地表裁片） |
| --- | ---: | --- | --- | --- |
| `surface`（现状） | 207205 | ✅ 2.88px / near 79 | ❌ good=11 near=0 | ✅ 0.00px / near 144 |
| `k100`（合成**替换**地表） | 207423 | ✅ 2.88px | ✅ 0.01px / near 88 | ❌ near=0 |
| `k035`（替换，底片×0.35） | 196379 | ✅ 2.88px | ✅ | ❌ |
| `both`（地表**并存**合成） | **223432** | ✅ **2.88px / near 79** | ✅ **0.01px / near 88** | ✅ **0.00px / near 144** |

三个结论：

1. **`surface` 包的关键点数 207205 与已发布的 `jinzhou` 包完全一致** —— 控制组可信。
2. **现状包在洞窟里锁不住**（good=11、near=0）；合成后能锁住（0.01px、near 88）。
   这正是"层内没有素材"的实证。
3. **"替换"会让地表视图在同一坐标失效**（near 从 144 掉到 0），**"并存"两边都能锁**。
   担心过的 `inlierRatio` 稀释没有发生：洞窟查询在 `both` 下 good=121（`k100` 是 110）、
   near=88 不变 —— 比值检验把另一套纹理的匹配滤掉了。

**因此方案定为：地表瓦片全部保留，把 `k=1.0` 的合成瓦片以同一坐标追加进同一个包。**
今州代价是 +16227 个关键点（+7.8%）；`k<1` 一律不要（既丢地表外观又少 5–6% 特征）。

> 仍未验证：查询用的是地图瓦片 1:1 裁片，**不是真实小地图渲染**。它能比较各包之间的优劣，
> 不能当作绝对精度声明；层内真实小地图的实机验证仍是最后一道门。

## 一、目标

让工具在**层内**（今州：叩天关 3 层、环木阙 3 层、眠龙庭 2 层、寒雾深坑 1 层）也能定位小地图，
且**不改运行时接口、不改坐标换算、不动点位数据**。

## 二、已确定的事实（不再需要讨论）

| 事实 | 数值 |
| --- | --- |
| 分层瓦片形态 | RGBA 叠加层，不透明像素仅 0.1%–6.2%（眠龙庭·上层 (3,−3) 为 100% 透明） |
| 合成后每层特征 | 380（底片×0.20）～ 9215（底片原亮度），门槛 `inlier ≥ 12` |
| 分层瓦片网格 | 与地表瓦片**同一套 `x_y`**，所以合成后坐标天然正确 |
| 叠加层与 `(floorId, level)` 的对应 | 完全一致（928 个带楼层点位的 `(floorId, level)` ↔ `layer.id, floor.id`，0 孤儿键） |

## 三、方案 A（推荐）：把分层合成瓦片的特征并进现有地区包

1. **归档**（新增 `scripts/Get-MapLayerArchive.ps1`，或扩展 `Get-MapTileArchive.ps1`）
   - 下载 `mcmap/layer/<版本>/<state>/layer.json`；
   - 按 `floors[].tiles` 下载分层瓦片，保留 `<state>/<layerId>/<level>/<x>_<y>.png` 布局；
   - 今州 17 张、state 8 共 77 张（最大 134 KB），体量与现有归档比可忽略。
2. **合成**（新增 `scripts/New-LayeredTileComposite.ps1`）
   - 对每个 `(region, tile)`：`out = 地表瓦片 × k` 再 alpha-over 当前层叠加层；
   - 输出**不透明 PNG**，保持 1024×1024，文件名沿用 `<state>_<x>_<y>.png` 语义；
   - `k` 可配，先各建一套 `k = 0.20 / 0.35 / 1.00` 用于实机选优。
3. **打包**：把合成图当作普通瓦片喂给现有 `KuroMapFeatureBuilder.exe`（它只校验 sha256 与
   1024×1024，不关心来源），**与地表瓦片同时列进同一个 manifest** —— 同一坐标同时拥有
   "地表纹理"与"层内纹理"两套特征（A/B 里的 `both` 包，已验证两边都能锁）。
   注意：**不是**用地表图替换，替换会让地表视图在同一坐标失效。
5. **发布**：作为地区差分包更新，沿用现有资源包流程。

**成本**：今州 5 张坐标需要合成（共 17 张分层瓦片本体），新增 16227 个特征（现有 207205 个），
相对 `features.imf` 111 MB 属于噪声级。

## 三·五、脚本

| 脚本 | 作用 |
| --- | --- |
| `scripts/Get-MapLayerArchive.ps1` | 归档 `layer.json` + 分层瓦片到 `map-regions/layers/<代次>/`（161 张 / 19 MB，已跑通） |
| `scripts/New-LayeredTileComposite.ps1` | 合成：`地表 × k` 再 alpha-over 叠加层；未分层的瓦片用硬链接复用 |

## 四、方案 B（暂不做）：每层一个包 + 运行时楼层状态

- 今州 9 个包，每包 1–3 张瓦片，成本同样很低；
- 但**只有当需要"自动判断玩家在第几层"时才有必要**。x/y 定位在方案 A 下已经正确
  （各层共用底片、共用网格，锁到"错误的层"仍然给出正确的 x/y）；
- 楼层身份建议走点位侧：`(floorId, level)` 过滤 + 分层入口 `FCRK`，与官方前端两条分支一致。

## 五、必须验证的三件事（按顺序）

1. ~~**同一坐标两套纹理会不会互相拖累匹配质量。**~~ **已离线验证：不会（见第零节）。**
   `inlierRatio` 没有被稀释：`both` 包在洞窟查询上 good=121 / near=88，与只有合成纹理的
   `k100`（110 / 88）几乎相同 —— 比值检验把另一套纹理的匹配滤掉了。地表参考图在四个包下
   完全一致（84 / 79 / 2.88px）。
2. **层内真实小地图能否锁定。** 离线用的是瓦片裁片，不是真实小地图渲染。需要在叩天关/眠龙庭
   各截一张真实小地图跑 `referenceVerification`（门限 8px）。
3. **层内连续移动是否掉锁。**
   - 沿用现有实机步骤（走位 + 记录 `coordinate-recovery` 事件），检查层内 `Tracking` 占比与
     地表侧不回归。

## 六、验收标准

- 层内参考小地图 `errorPixels ≤ 8`（现有门限）；
- 地表参考小地图误差不增大（不回归）；
- 层内连续移动 N 秒内不掉锁（N 沿用既有实机标准）；
- `scripts\Test-KuroMapFeaturePack.ps1` 通过。
