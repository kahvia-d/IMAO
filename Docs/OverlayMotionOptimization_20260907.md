# 地图标记运动流畅度优化（2026-09-07）

> 后续说明（2026-09-08）：本文记录的时间平滑方案已被地形图像跟随替代，以处理用户反馈的浮动与跟手滞后。当前实现与验证见 [地形图像跟随与小地图浮动修复](ImageAnchoredOverlay_20260908.md)；下文保留为上一版的历史记录。

## 原因

标记原先以 20 FPS 绘制，通常每 80 ms 接收一组定位坐标，两次定位之间直接重复同一组屏幕位置。提高定位精度并不能消除这种阶梯式移动。

大地图的帧间预测还会丢弃小于 0.5 跟踪像素的平移和小于 0.3% 的缩放，同时把参考图像更新到当前帧。连续慢拖时，每一步都可能被丢弃，直到视觉定位重新校正才跳到正确位置。256 像素跟踪图像上的位移门槛也会随游戏画面分辨率放大。

本次检查了最新的 `events-20260907.jsonl`。22:13–22:18 的运行包含正常的小地图局部定位和大地图帧间预测；末段小地图局部匹配多在数毫秒内完成。代码中的绘制频率和坐标发布方式是两个界面共同的连续性限制。

## 改动

- 绘制目标由 20 FPS 改为 60 FPS，使用高精度等待计时器控制节奏；失败时回退到普通等待。定位更新间隔继续遵守原配置。
- 新增只影响显示的平滑变换，以采集时间计算运动，在定位更新之间平滑衔接。短时预测最多覆盖 80 ms，平移前推上限为小地图 8 屏幕像素、大地图 24 屏幕像素，缩放前推上限为 2.5%。这些显示估计不会回写给定位器。
- 交替跳动的定位噪声不用于预测方向。采集停止后，预测退回最后一次测量值；失去可靠定位、切换场景、传送、画面尺寸变化或界面隐藏时重置。保持之前的界面可见性检查。
- 标记和路线使用同一个平移、缩放变换。标记候选区域增加边缘余量，小地图在变换后按实际圆形范围筛选。
- 记录真正显示过的快照。鼠标命中、采集快捷键和路线编辑使用显示位置，避免平滑处理后操作错位；该快照超过 100 ms 或界面已隐藏时禁止操作。
- 大地图使用局部图像块匹配、双向一致性检查和梯度亚像素细化。较大拖动、缩放保留 ORB 匹配作为回退；最终模型仍限制为平移与统一缩放，并检查特征的空间分布。
- 短距离内对照同一张带有定位参考的图像，避免逐帧累计重采样误差。小位移持续累计到可应用的程度，不再直接丢弃；移动较远或缩放较多时更换参考图像。
- 增加 `overlay-motion` 日志，记录实际绘制帧率、定位快照更新率和快照年龄，便于后续游戏内检查。

主要实现位于 `IMao-Core/src/Runtime/OverlayMotion.h`、`App/MapViewportPredictor.cpp`、`App/App.cpp` 和 `ImguiDraw/ImGuiOverWindows.cpp`。

## 验证结果

证据目录：`out/motion-smoothing-20260907/`。

- Release 核心构建成功，原生测试全部通过。
- 106 项托管运行时检查通过，包括实际 CoreHost 启动、配置、重启、退出及管道行为。
- 发布资源检查通过：`resourcesReady`、`visualReady`、`viewportReady` 均为 `true`，错误为空。
- 原生运动测试覆盖匀速移动、采集停止、界面重开、传送、定位恢复、缩放一致性、输入坐标逆变换和长时间采集间隔。
- 在固定 80 ms 采样、16 ms 绘制的匀速模拟中，40 像素/秒移动的最大单帧跳动从 3.2 降至约 0.64 像素；200 像素/秒从 16 降至约 3.20 像素，均约减少 80%。这是合成回放指标，不是实际游戏 FPS 测量。
- 使用合成图案及已有真实游戏大地图截图，各回放 40 帧缓慢平移／平移加缩放，再保持 20 帧静止。四组最终中心和宽度误差均小于 0.03 跟踪像素；静止时无持续累计漂移。较大的同时拖动、缩放和空白图像失效检查也通过。
- 本次运动图像回放总耗时约 2.66 秒，包含两种图像和多种场景；不代表实时绘制耗时。

新版核心已生成在 `x64/Release/IMao-CoreHost.exe`。从原来的 WinUI 入口重新启动即可加载。

尚未完成这版在实际游戏中的人物走跑、快速反向、连续滚轮缩放和拖动后的跟手体验测试。实际 FPS 取决于机器负载与捕获方式，可结合新增帧率日志确认。
