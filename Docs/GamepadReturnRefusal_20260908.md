# LB → B 返回游戏失败修复

## 实机证据与原因

2026-09-08 20:53 的实机日志表明，LB 打开路线工具栏时，普通前台请求已被 Windows 拒绝，必须附加原游戏的输入线程队列才能取得透明输入窗口的焦点。原来的 B 返回路径仅调用普通 `SetForegroundWindow(game)`，没有对应的跨进程处理。

20:53:05 松开 B 后，路线输入结束，随后普通返回请求连续失败，500ms 超时后，真实前台仍是透明输入窗口；重复 B 也走同一条失败路径。直到 20:53:14 用户把焦点切回游戏，输入窗口才被回收，地图状态恢复。手柄原始采样在整个过程中一直正常。

第二个问题是原生显示权限与手柄操作会话绑定：会话一结束，透明输入窗口就不再算允许显示叠加的前台；此时游戏还未取得焦点，所以两种状态栏一起隐藏。后续的“地图画面不可用”还覆盖了最初的 B 退出原因。

日志摘录保存在 `out/gamepad-return-refusal-20260908/field-reproduction.jsonl`。这些是本次实际游戏现象的证据；下文的修复测试使用隔离窗口，不冒充已在游戏中复测。

## 修复

1. 普通返回请求后先短暂等待已排队的激活。如果仍停留在原透明输入窗口，重新核对游戏 HWND/PID/TID、响应性和当前前台，执行一次真正的跨进程输入队列附加；同步请求完成后，立即在 `finally` 中解除附加。附加期间没有 `await`、XAML 或 UI 分发。
2. 仍要求解除附加后连续两次观察到原游戏前台，才回收透明输入窗口。中途切换到其他应用立即取消，不反复抢焦点。普通请求、是否执行附加后的请求、实际前台、附加/解除错误分别记日志。
3. 手柄操作结束与状态栏显示分开。只有已经真实取得过焦点的原窗口/进程/线程身份可以保留最长 15 秒的只读显示，期间全部路线操作停用。返回失败时显示“松开全部按键后按 B 重试，或点击游戏窗口”；关闭匹配状态栏后，路线栏仍有提示。
4. 状态消息按已结束会话、返回尝试和真实前台核验，不能恢复手柄操作。重复 End/Clear 不延长期限、不覆盖最初退出原因；窗口销毁、AltTab、身份或档案变化以及到期会撤销显示。尚未到期的失败状态收到一次明确 B 重试时，可以开启新一段 15 秒显示；轮询不会续期。
