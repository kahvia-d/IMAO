# 核心重构记录（2026-09-07）

本次工作承接 [项目审计](ProjectAudit_20260907.md)，保留现有 WinUI、独立 CoreHost、库街区资源格式和已验证的几何约束，重构运行配置、帧数据流、后台定位和会话生命周期。没有替换用户的点位进度、路线和资源包，也没有把未校准场景直接开放。

## 1. 配置由服务统一管理

`RuntimeConfiguration` 是不可变配置对象，集中约束截图方式、刷新间隔和四项显示开关。`RuntimeConfigurationStore` 负责兼容旧版状态栏配置、原子保存、损坏文件备份和读取错误报告；文件写入成功后才更新内存状态。

`CoreHostService` 在每次新连接握手后重新发送完整配置与当前筛选项。更新配置与连接、重启共用生命周期锁，因此并发操作不会把新配置发给已经失效的核心。配置先作为期望状态持久化，连接失败时仍可在下次启动恢复。

首页和功能页只从该服务回填控件。初始化、页面切换、重启不再发送默认值覆盖用户选择。刷新范围统一为 16–1000 毫秒，程序运行时禁止在首页切换截图方式。

启动页还移除了每次启动都会弹出的旧覆盖率提示。Windows 窗口优化兼容选项改为默认关闭；用户主动启用时只更新 `SwapEffectUpgradeEnable`，保留同一注册表值中的其他偏好，并报告修改失败。本轮没有实际写入系统注册表。

## 2. 截图、绘制与快捷键共享完整帧

新增 `SnapshotChannel<T>`、`CapturedFrame` 和 `OverlayFrame`。生产线程发布整份不可变对象；读取者持有自己的快照，生产者发布下一帧不会改变已读取的数据。

```mermaid
flowchart LR
    Capture[截图：图像、实际帧号、尺寸、时间] --> Captured[CapturedFrame]
    Captured --> Detection[界面识别]
    Captured --> Location[玩家定位与视口预测]
    Detection --> Publish[主循环组装完整帧]
    Location --> Publish
    Publish --> Frame[OverlayFrame：视口、玩家、点位、路线]
    Frame --> Render[绘制线程]
    Frame --> Hotkey[点位标记与路线录制]
```

- WGC 使用实际捕获帧号；重复读取同一 GPU 帧不会变成第二份独立定位证据。界面识别同样跳过重复帧。
- 默认设置下，画面停止更新超过 500 毫秒后不再绘制或接受快捷键操作；用户主动选择较慢刷新时，过期窗口为至少两个刷新周期；窗口尺寸变化时不使用旧尺寸下的投影。
- 地图点位、路线和录制坐标使用同一份实际用于绘制的预测视口，避免拖动/缩放时录制位置落后于画面。
- 小地图当前帧定位失败时清除旧标记，避免把旧投影继续贴到新画面上。
- 移除每 10 毫秒更新调试鼠标坐标的后台线程，改为读取画面快照时按需计算。
- 移除没有调用者的同步大地图定位、旧移动判定和旧场景识别入口及其专用状态，避免同时维护两套视口流程。

这不是对所有原生共享状态的全面形式化证明。界面检测仍通过已有状态控制器与主循环协作，但绘制和用户快捷键已不再逐个读取其可变容器。

## 3. 定位任务可以取消，恢复工作分帧执行

`ExactDescriptorMatcher` 分批计算精确 L2 距离，同一距离矩阵同时得到正向最近两个邻居和反向最近邻。它保留原 BF 匹配的邻居、距离与相同距离时的顺序；没有放宽 RANSAC、尺度、象限、重投影误差或两帧确认门槛。

`FeatureRowCache` 复用去重后的不可变区域特征，描述子、关键点和行号键的数据预算为 64 MiB，不包括容器自身开销。去重仍要求坐标和完整描述子同时相同；不同地点的相同外观必须保留。正在读取的数据可以在缓存淘汰后存活，因此该数值不是整个进程的内存上限。

分段计时发现区域首次准备时反复哈希完整描述子成本很高。去重索引改用混合后的坐标位模式计算哈希，冲突时仍逐字节比较完整描述子，并预留桶容量。同一诊断截图中，两个区域的首次准备耗时由约 133/61 毫秒降为 47/22 毫秒。精确匹配按查询规模选择批量，距离缓冲区目标为 2 MiB，减少小地图查询反复调度 OpenCV 工作线程的开销。

全包仿射验证与平移候选共享一次描述子匹配。小地图恢复不再在一个请求内连续尝试全部角度：每帧先检查实际方向，必要时逐步尝试其他方向。后台请求设置 350 毫秒搜索预算，在批次边界检查取消和预算；不完整搜索会标记 `searchIncomplete` 并拒绝发布。

大小地图均使用请求代次使取消、替换和关闭前的结果失效。图像提取、OpenCV 索引训练等单次调用无法在内部中断，因此时间预算并非硬实时保证。尤其大地图首次 FLANN 索引构建仍需单独优化。

## 4. 会话与显卡资源生命周期

`OverlaySession` 统一拥有 App 与叠加层。正常停止、部分启动失败和异常退出均按路线录制、绘制、App 工作线程、通知的顺序清理，避免后台任务持有已销毁 App 的指针。

生命周期监控会发现主循环或绘制线程意外停止，保留故障状态并释放会话；不会继续显示运行中。工作线程创建失败会清理已经创建的线程。

图标纹理属于创建它们的 D3D 设备。重启或设备重建时清空纹理缓存；重建设备时也重新初始化 ImGui 的 D3D 后端。绘图函数使用作用域清理覆盖初始化中途退出和异常路径。显卡提交失败会结束会话并让界面进入故障状态。

这些路径已编译检查，显卡设备丢失与游戏关闭/挂起仍需要实机故障注入，不能用截图回放替代。

## 5. 点位数据与绘制类型解耦

`Domain/MapData.h` 集中定义点位、路线和 `MapLayerIdentity`。点位从库街区 JSON 读取并保留 state、country、floor、level，屏幕投影复制身份，不再丢弃楼层字段。

保留身份不代表已经实现自动楼层识别。当前没有足够的楼层真值与校准素材，运行时尚未据此切换楼层或隔离全部重叠区域。三个未验证新场景保持关闭。

绘图窗口头文件改为前向声明 App，构造实现移到源文件，减少绘图类型对 App 全部识别依赖的间接引用。

## 6. 构建缓存

原构建入口每次传入 `--fresh`，会删除包含目标文件的 CMakeFiles，导致正常构建也变成全量编译。现在记录实际 MSVC 编译器、工具集和 Windows SDK 身份：默认增量构建，工具链变化或显式 `-FreshConfigure` 时清理，继续避免新旧编译器与 STL 混用。

## 7. 验证

最终代码已通过 Release 核心与 WinUI 构建、原生优化测试及 90 项托管运行测试。托管测试实际启动独立 CoreHost，通过管道验证配置恢复、并发重启、错误请求和退出行为。原生测试覆盖精确匹配与原 BF 结果的一致性、跨批次取消、描述子所有权、缓存淘汰、完整帧并发发布、画面过期和慢刷新适配。

同机、同一组 29 张小地图回放的前后比较如下；性能数字是本次运行的观测值：

| 指标 | 重构前 | 重构后 |
| --- | ---: | ---: |
| 成功全局定位 P95 | 256.38 ms | 135.93 ms |
| 全部全局搜索 P95 | 5153.96 ms | 218.58 ms |
| 局部跟踪 P95 | 37.91 ms | 9.18 ms |
| 原始强候选次数 | 24 | 24 |
| 最终发布次数 | 8 | 8 |
| 已标注样本的误接受次数 | 0 | 0 |
| 回放验收 | 未通过耗时门槛 | 通过 |

29 张素材中仅 4 张有坐标真值，按两帧确认发布其中 2 次；其余 6 次发布没有真值，不能计入准确率。本轮为这两次必要发布增加了强制断言，避免以减少定位输出换取性能通过。负例增加单次搜索 500 毫秒检查，本次无超时违例。方向恢复改为跨帧执行，前后单次请求工作量不完全相同；上表“全部搜索”同时反映工作预算和实现优化，不能只归因于匹配器提速。

其他验证：

- 大地图 8 个回放用例全部通过，包含 6 个接受和 2 个拒绝；它们不是 8 个独立地图区域。首次索引构建仍约 3.83 秒。
- 取消回放 4/4 完成旧请求隔离检查，两次必要发布均正确，未接受过期请求。该组是新增回归，不计入上述 29 张比较。
- 空清单返回 2，缺图和无真值清单返回 3；无输入或无可验收证据不会显示成功。
- 本地库街区数据审计通过：23,803 个点位、527 个图标、506 个筛选标识；资源就绪、大小地图索引就绪三项均为 true。本轮使用当前本地资源快照，没有重新同步线上数据。
- 正式构建入口报告 `ninja: no work to do`，App 目标文件时间戳保持不变，验证增量缓存有效。已有编译告警仍需逐步清理；最后一次无改动构建的零告警不代表全量构建零告警。
