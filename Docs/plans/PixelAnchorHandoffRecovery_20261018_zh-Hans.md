# 实测像素锚点恢复与独立来源健康

用户在22:29:06–22:33:23的实机试跑后反馈仍有较多闪烁，并授权继续修复。此次只改原生连续性与交接逻辑；保留map-test当前的173来源自训YOLO候选权重及识别规则。

## 证据

原始分析与红绿日志位于主检出 `out/evidence/flicker-live-20261016-222906/`。该会话63次来源切换，其中12次从OCR交回SURF后不到500ms又退回OCR。39条限流掉绘记录全部reliable=1，30条primary-track、4条fresh-source-track、5条source-anchor。完整统计窗口中430个跟踪失败帧减去34个大地图贴合失败帧，得到396个小地图未绘制帧；不能将其当作396次独立闪烁。

648/679次OCR给出候选，推理中位16.53ms；候选数不等于正确数。30条primary-track中17条源到当前截图间隔超过250ms。既有每源一次的严格重配准恢复有运行，但它仅能使用定位器发布的source截图，无法利用绘制端已经成功配准过的更新截图。

## 改动

- ImageAnchoredOverlay仅额外保留最近一次实测成功截图、截图时间和原锚点到该截图的变换。旧参考失败且原source过旧或已失败时，可由这份不超过250ms的已配准像素再做一次同门槛配准；每份参考最多尝试一次。成功时显式转换anchorToSource的坐标基准，后续移动仍相对原source计算。缓存替换而非累积整段图像历史；不依赖速度外推或OCR坐标证明像素有效。
- 场景、UI代际、裁切区域等上下文不能延续时重新锚定并替换最近像素。没有当前像素证据或参考超过250ms仍拒绝；150ms屏幕变换复用上限不变。大地图不启用这条新增恢复路径。
- CoordinateHandoff记录局部与全局SURF各自健康状态。一个来源失败不会覆盖另一份尚在500ms有效期内的独立成功；所有可用来源失败或过期仍立即加速OCR。传入失败截图时间，晚到旧失败不覆盖更新成功，晚到旧成功也不能治愈更新失败。OCR不能修复SURF健康，750ms交回观察仍在。
- App待命读数的接管由独立来源健康、有效位置锁和原有停滞检测决定。RecoveryController同时记录全局搜索失败，因此其Suspect/Recovering标签不再单独触发OCR抢占一份新鲜独立SURF定位。位置预算、镜像和区域等门槛未放宽。
- 诊断新增recent-capture恢复路径、重试跳过原因、连续掉绘开始/结束及持续时间、失败来源截图时间和NeedsReadout前后状态，下一次可比较中断时长而非每秒限流条数。
