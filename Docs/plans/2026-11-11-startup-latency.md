# 启动提速 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement and review each task.

**Goal:** 缩短玩家版启动等待，尽早显示主窗口，保留完整校验、更新回退与明确故障信息。
**Architecture:** 先优化启动器完整文件校验并记录各阶段耗时，再把主程序资源准备移到已显示窗口之后。地图相关操作在准备完成前不可用。禁止以缓存或时间戳替代完整性检查。
**Tech Stack:** C# / WinUI 3 / .NET 8 / PowerShell。
**Spec:** 用户已批准本对话中的两步方案：测量并优化校验、提前显示界面后台准备资源。

## Constraints
- 不改 C:/Dapps/IMao，不更改其快捷方式；仅只读分析。开发测试树允许代理自行关闭、脚本整树刷新、重启。
- build/test/publish 前 Enter-DevEnvironment；托管/XAML 变更需要真实 WinUI 自包含 publish。
- 不删改已有测试断言，不削弱文件、目录、签名、回退检查。
- 不新增校验缓存，不承诺与无启动器的测试版完全相同的耗时。

## Tasks
- [x] 启动器：测量原串行与有限并行完整校验；只保留有收益的并行实现；进度单调、失败/取消不放行；增加计时日志与回归。
- [x] 主界面：尽早显示符合现有主题的主窗口准备状态；资源未完成不启动依赖服务、不允许探索；异步准备成功进入正常首页，失败直接显示；关闭期间不继续启动。验证真实 WinUI。
- [x] 启动入口：检查本机快捷方式和生成脚本，避免主程序→启动器→主程序的重复初始化；若已直达启动器则无需修改。仅修改仓库实现，保持旧入口兼容。
- [x] 集成：回归、性能对照、独立审阅、真实发布，刷新测试树，哈希 differing=0，重启。

## Review focus
关闭时初始化尚未结束；初始化失败；并行校验损坏/多余/缺失文件；报告进度倒退；更新试运行健康确认必须仍等待正确的资源就绪；旧快捷方式兼容。
