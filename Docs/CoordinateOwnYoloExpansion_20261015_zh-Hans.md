# IMao 自训字符检测：扩充不同坐标与背景

在[首轮原型](CoordinateOwnYoloPilot_20261015_zh-Hans.md)之后，从已有训练池增加 40 张不同坐标的真实素材，补充草地、雪地等背景的字符框。固定开发集的完整 XYZ 结果由 **0 正确 / 4 错误 / 166 未返回**改善至 **133 正确 / 5 错误 / 32 未返回**。自训模型已经有明显识别能力，但仍落后于既有 OCR 候选和网友模型，不具备正式接入资格。

本轮仍使用官方通用 COCO 初始化，自行训练专用字符模型。没有使用网友游戏坐标权重、伪标签、字符框或其解析器。YOLO11n 算法和 Ultralytics 8.3.228 框架归属上游，原始分发为 AGPL-3.0；本项目完成专用标注、权重训练、自行实现的解码与评测。

## 数据与标注

从 paired-v3 既有 train 分区，按背景各取 8 张不同坐标图，共 40 张。选择依据是场景分组和已有坐标字符串，没有依据本轮开发预测挑训练图。新增字符框 1,294 个；与原来的 27 张静止训练图、864 个字符框合并后：

| 有文字训练图 | 67 |
| 不同 XYZ | 42 |
| 字符框 | 2,158 |
| 原有背景负例 | 9 |
| 训练总输入 | 76 |
| 新增绿色／黄色草地、橙色草地、雪地混合、冷色岩石、暗色地面 | 各 8 |

坐标沿用既有自采图视觉核对标签；日期、时间到 +8 逐张查看原色放大图转录，没有按帧号推算时间。依据清晰锚帧的字体格提出框，再查看五张覆盖全部 40 图的原色叠框页，核对数字顶横、末位数字、负号、逗号、加号及日期文字。框是助手复核的近似字体格，不是用户人工逐像素金标。字符检测训练没有把日期数字留作未标目标。

固定开发段、776–787 整组留出和第 1100 帧均未用于训练。没有改写旧坐标基准。六张历史正 X 训练来源因 HUD 几何不同，本轮没有直接套用字符框；当前新训练仍全部为负 X，正 X 识别尚未覆盖。

## 实际原生输入与训练

输入保持固定 readout-line ROI，原色 892×48，包含坐标与日期时间。训练、开发均使用实际编译的原生程序输出，不使用坐标标签裁掉日期，也不向推理传入真值、小地图或上一帧位置。

准备时发现 Python cv2 5 的 cubic 缩放与已编译原生程序存在少量最大 1 灰度级差异，初次严格像素断言失败。随后保留近似图和诊断记录，直接运行原生程序生成新增 40 张训练输入；没有降低像素一致性标准来宣称近似图相同。叠框图与实际输入仅有上述低位像素差，不涉及几何移动。原有 27 张继续使用既有原生输入。

复用本机已有 GPU 环境和官方 `yolo11n.pt`，本轮没有新下载。与旧 200 轮试验使用相同配方：官方 COCO 80 类初始化，重置为本项目 14 类；AdamW、lr0=0.001、batch=8、imgsz=896、rect、seed=20261015，关闭翻转、mosaic、mixup、颜色及几何增强。固定 200 轮最后的 last.pt，不按开发分数选 checkpoint。实际训练约 370 秒，以本机日志为准，不作为性能基准。

框架 val=train，只用于拟合观察，mAP 不作为开发准确率。扩大数据后，每轮更新次数也增加；相同轮数不等于相同计算预算，因此不能把改善严格归因于数据多样性这一项因素。

检测分数仍为 0.25，NMS IoU 仍为 0.45。完全复用上一轮解码器，摘要一致，没有为了这轮成绩调阈值、补负号或放宽完整坐标语法。

## 错误和未返回的具体问题

| 帧 | 既有坐标 | 本轮错误返回 |
|---|---|---|
| 149 | (-505,2005,53) | (-505,2005,553) |
| 469 | (-1353,1997,156) | (-1353,1997,1) |
| 480 | (-1463,1992,251) | (-1463,1992,2) |
| 481 | (-1470,2001,250) | (-1470,2001,2) |
| 1071 | (-1056,-5588,558) | (1056,-5588,558) |

高置信度的局部数字也不能保证完整坐标正确，例如 480 帧末位字段残缺仍被当成整数返回。缺字符后，现有空间分组有可能把残片切开，使部分 Z 字段通过语法；负号漏检又可能直接改变 X 符号。不能仅凭提高一个分数门槛解决。

32 张未返回中，23 张是整帧字符冲突拒绝，9 张没有唯一完整三元组。另做只读诊断：先按预测框空间分组，再查看冲突所在组；23 张冲突拒绝中有 15 张只在不含坐标逗号的上下文组发生冲突，含两枚逗号的组本身没有此类冲突。这说明整帧拒绝会被日期干扰，但**不证明这 15 张坐标全部正确**，也没有将它们改计为正确。778 帧仍因字符冲突未返回，780 帧已正确。

下一轮应分别处理两件事并保留对照：先按空间组定位冲突，避免日期影响其它组；同时加强坐标完整性检查，防止漏尾数后接受局部字段。随后增加三位 Z、正 X 与困难背景的训练覆盖。不能只放宽拒绝规则提高返回率。
