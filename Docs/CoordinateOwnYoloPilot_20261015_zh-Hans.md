# IMao 自训字符检测：首轮拟合与 ONNX 链路

用户要求使用自行训练的专用模型，不能把网友训练好的游戏坐标权重当成自身成果；随后明确同意以官方通用预训练权重初始化。本轮完成自有字符框、小规模 GPU 训练、自行实现的坐标解码，以及 ONNX Runtime CPU 回放。**链路可工作，识别质量未通过，不能接入正式客户端。**

没有使用网友的游戏坐标权重初始化、生成伪标签或提供字符框，也没有复制其坐标解析代码。使用的 YOLO11n 算法和 Ultralytics 框架仍明确注明上游来源；本项目完成的是专用标注、训练权重、坐标解码与验证，不声称 YOLO 算法原创。

## 首批自有字符标注

复用自采会话中已核对的 744–753、884–900 两组，共 27 张图。坐标及逐帧时钟文字来自既有助手视觉复核记录，不用网友 OCR 输出或插值时钟作真值。仍然不是用户人工逐字金标。

在两张清晰锚帧上，用经典像素投影提出字符框，随后在原色图上逐字查看；相同 HUD 布局传播到对应的静止组。初稿 TopHat 丢掉了部分 7 的顶横和 + 的横臂，原色图复核后，在独立保留的 `pilot-v2` 中扩大相应字体格，才开始训练。没有将初稿的截断框拿来训练。

每张图标注完整坐标及可见日期时间到 +8，共 32 个字符、合计 **864 个框**。只标坐标而把相同日期数字当未标目标的问题在此批中没有出现。另取 9 张训练来源顶部无文字区域，生成背景负例。合计 36 张训练输入。

实际输入是既有原生程序生成的 892×48 raw 原色图；没有切掉日期，也没有给推理器坐标真值或标签辅助边界。训练负例是训练来源的上方背景，不是额外独立的 UI 负例。

这批数据只有两个坐标位置，草地占主导，**未纳入雪地训练图**。它只适合检验训练与部署链路、观察小样本拟合，不能代表成熟训练集。776–787 整组及其他开发图没有进入训练。

## 两组固定预算训练

两组均从同一官方通用模型开始，不从网友权重或前轮专用 checkpoint 续训。固定 36 张输入、14 类、batch=8、rect、imgsz=896、workers=0、AdamW、初始学习率 0.001、最终比例 0.01、seed=20261015。关闭水平／垂直翻转、mosaic、mixup、旋转、缩放和颜色增强，先检查拟合。关闭 AMP 自动模型检查及依赖自动安装，避免额外模型下载。

先固定 40 轮，观察到许多数字已有响应，但逗号和负号等符号在固定 0.25 检测门槛下召回不足。保留这份失败证据后，再固定 200 轮进行拟合预算对照；不改变输入或解码门槛。学习率日程随总轮数延展，不能声称每一步学习率都与 40 轮完全相同。两组均使用固定最后一轮 `last.pt`，不按开发集挑选 best。

框架的 val 清单与 train 相同，明确只作拟合诊断。官方训练验证的 mAP 不作为留出准确率。CSV 核验实际完成 40、200 轮；耗时约 47、221 秒，仅为本次本机运行记录，不是速度对标。

## 自行实现的坐标解码

使用检测框、字符类别与分数，自行按水平位置分组；要求完整出现三个整数和两枚逗号，保留实际正负号，不补缺失字符。模糊重叠字符、多个候选、数字与日期粘连、缺逗号及整数溢出均拒绝。框架的检测／NMS 仍来自已注明来源的 Ultralytics；本项目新增的是坐标语法与空间分组。

固定检测分数 0.25、NMS IoU 0.45。没有从正确坐标中选择检测结果，也没有位置先验、上一帧坐标或小地图标签进入推理。8 项解码测试先在模块缺失时变红，再通过实现，包括日期分组、显式加号、缺逗号、粘连日期、多候选、字符重叠、空输入、低分字符和溢出。

这是保守原型，不是成熟解码器。例如当前对整幅图中的字符冲突会拒绝整帧，日期上的冲突也可能影响坐标返回；但也已观察到坐标本身的错误，不能将全部低成绩归因于解码。

## 实际结果：拟合与开发分开

逐图回放 27 张训练来源、170 张开发 XYZ、141 张无坐标、8 张待定，所有模型输入清单不含真值。完整 XYZ 计分：

| 自训原型 | 训练来源正确 / 错误 / 未返回，27 张 | 开发正确 / 错误 / 未返回，170 张 | 无坐标误报 /141 |
|---|---|---|---:|
| 40 轮 | 0 / 0 / 27 | 0 / 0 / 170 | 0 |
| 200 轮 | 26 / 0 / 1 | 0 / 4 / 166 | 0 |

200 轮在训练来源中的 864 个字符，按相同类别、IoU≥0.5、检测分数≥0.25 独立匹配，负号 118/118、逗号 53/54、加号 27/27、冒号 54/54。数字类别仍有少量遗漏。它确实学会了这批输入，而不是仅在框架中产生了 checkpoint 文件。

但没有可采用的开发表现：留出草地 12 张均未返回，雪地混合 40 张也均未返回。第 771、772 帧将实际 X=-582 读成 -557，后者恰好是其中一个训练坐标；第 605 帧将 (-429,1019,11) 返回为 (-420,1010,11)，第 616 帧丢掉 Z 的末位 1。训练来源字符与空间覆盖过窄，泛化明显不足；这些观察不能证明所有问题只有“记住坐标”一个原因。

这个仅两个位置的小试验不能与网友成熟权重公平比较训练能力，但明确尚不具备接入资格。网友既有同源 170 帧管线为 167 正确、1 错误、2 未返回；没有借其输出改善本轮训练或解码。

## ONNX CPU 链路

200 轮自训权重已经导出 ONNX opset12，输入 `[1,3,64,896]`、原始输出 `[1,18,1176]`。图检查通过，14 类顺序与训练一致。使用 ONNX Runtime 1.31.0 的 CPUExecutionProvider，复用官方框架预处理与 NMS，并调用本项目解码器。

346 张图的最终 XYZ／未返回与 PyTorch **346/346 一致**。这包含大量共同未返回，不是准确率。另取 12 张清晰、草地、留出与雪地图，将 PyTorch 预测器实际张量直接送入 ORT；原始输出最大绝对差 0.00079346，证明相同输入下导出计算基本一致。没有以 ONNX 一致率掩盖开发集 0 正确的事实，也未修改 WinUI 或接入正式客户端。
