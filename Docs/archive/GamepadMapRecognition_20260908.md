# 手柄大地图识别问题分析

## 结论

根因是原大地图控件检测只支持键鼠的右侧“＋／－”布局。游戏切到 Xbox 模式后，这两个位置变成 RT/LT 胶囊图标，中间还增加右摇杆 R 提示；指南针仍在，但原检测无法提供有效的地图控件证据，叠加层和手柄入口随之停用。

## 现场证据

`map-ui-candidate-rejected` 同时记录备用结构检查未确认地图。稳定状态和当前画面可见性是两个阶段，所以日志中短暂出现“状态还是 BigMap，但 map=0”并不矛盾。

## 修复范围

保留原键鼠形状与颜色门槛，增加手柄布局分支。同一帧必须同时具有上下两个 RT/LT 胶囊、同轴的 R 指示器及上下金色箭头、左上地图指南针。识别依据是 UI 结构，不依赖玩家位置、地图中心、特定地形或键盘 M。

新截图回归还暴露了旧键鼠检测的候选选择问题：缩至 1280×720 后，首个“＋”候选为 `(28,28)`，首个“－”候选为 `(32,378)`，横向差 4 超出原有 3 像素限制；但同一帧另一个“－”候选 `(26,379)` 完全满足原形状条件，与“＋”只差 2。修复保留所有合格中心并寻找合法配对，保留原 `INTER_AREA` 归一化、形状阈值和对齐容差，不依赖刚好改变首个命中位置的插值方案。

新日志提供 `controlLayout=mouse/controller/none`、`controllerTriggerAnchors`、`controllerSlider`，便于区分布局未匹配与后续定位问题。当前画面证据过期、失焦和弹窗遮挡时的入口限制保持不变。

## 验证

回归样本位于 `Tests/MapUi`，保留原始分辨率与检测区域，仅遮去账号 UID；来源说明见 `Tests/MapUi/controller-map.md`。检查包括四种分辨率、BGRA、键鼠/手柄切换、无玩家定位冷启动、缺失单个控件、普通游戏、自定义标记弹窗以及即时证据失效。缩放和平移控件的变换测试是离线构造，不计作额外实机采集。

最终整包构建、6 个页面导航、地图资源校验、原生优化/点位/路线测试和托管核心通信测试全部通过。四种分辨率的截图结果均为手柄分支成立、键鼠分支成立、自定义标记弹窗拒绝；缺失控件与即时失效测试也通过。最终日志为 `out/gamepad-map-ui-20260908/build-final.log` 和 `out/gamepad-map-ui-20260908/runtime-final/`。

交付文件为 `x64/Release/IMao-CoreHost.exe`（2026-09-08 17:56:06）及同目录 WinUI 前端。修复后真实设备尚未复测；复测应关注普通手柄大地图是否稳定显示 `controlLayout=controller`，并保持上下两个锚点与中间缩放提示同时成立。

## 已知独立问题

手柄截图底部明确显示 L3 为“任务/位置追踪”。地图识别修复时的初版入口与它共用，长按无法消除这一冲突。随后用户提出用 LB 或 RB 替代，入口现已改为默认长按 LB 0.6 秒，并允许设置为 RB；L3 不再触发助手。肩键的具体实机响应仍需体验确认。
