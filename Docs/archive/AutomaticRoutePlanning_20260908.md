# 自动路径规划首版

后续补充了退出导航、保存路线删除、当前目标攻略快捷键和 WinUI 使用指南，见 [路线使用改进及最新验证](../RouteUsability_20260908.md)。

## 使用方式

1. 在「功能」页的自动路线区点击「新建自动路线」，打开游戏大地图并等待定位成功。
2. 选择矩形框选、自由套索或「加入当前视野」。选择使用当前显示类型中的未完成标记，连续操作会追加；已选点不会因拖图、缩放或筛选隐藏而消失。单条路线最多 500 点，超过上限时整次追加不生效。
3. 起点默认取本次打开大地图前的可信玩家位置。没有可信位置或地图场景不一致时，用「指定起点」在地图上点击，或返回游戏重新定位。地图中心不能作为玩家起点。
4. 点击「生成路线」查看编号、连线和目标清单，再点击「开始导航」启用。编辑或生成新预览期间，原活动路线保留。
5. 完成目标后点击「确认当前目标完成」，也可使用现有的单点完成操作。完成记录写入成功后才推进。跳过只影响这条路线，可撤销；取消点位完成后会按原顺序恢复该点。
6. 使用「保存活动路线」修改名称并保存，也可单独保存预览。重新启动后活动路线恢复为暂停状态，点击「继续」。只有「从当前位置重算」会重新优化剩余目标；重算结果仍需预览并启用。

套索松开自动闭合，边界点计入，自交按奇偶规则填充与选取。在矩形或套索工具中点按标记可增删单点；移动地图模式将地图上的拖动交给游戏。重叠点保留各自原始 ID，可展开逐点选择或明确加入整组。大地图选点时 Esc 在有手势时取消手势，否则切回移动地图。失焦、场景变化、定位失效或窗口几何变化取消未完成手势，保留已经确认的选择。

大地图绘制剩余访问连线；小地图强调玩家到当前目标。定位中断或进入其他场景时暂停动态指引，恢复同场景定位后继续。接近目标不会自动完成。楼层信息仅作提示，缺失时显示「未知」。

## 实现边界

- 原生 C++ 后台任务：固定起点的最近邻初始顺序，再执行最多 20 轮开放路径 2-opt，只接受缩短路径的调整。相同输入采用稳定 ID 排序，结果可重复；不同 ID 即使同坐标也独立保留。
- 成本为二维欧氏距离，界面称为「平面连线长度」。没有地形寻路、传送优化、自动移动、游戏米数或耗时估计，也不保证全局最短。
- 核心维护草稿、预览、活动路线和完成缓存；WinUI 通过现有 CoreHost 管道发出操作。异步结果和手势提交核对档案、场景与世代，手势另核对呈现时的修订号，避免旧输入覆盖新状态。
- 大小地图保留原线段邻接关系，在应用显示变换后逐段裁剪；端点在外但穿过视野的线段仍显示，不会因为删掉离屏顶点而产生额外连线。
- 文件位于用户应用数据目录的 `SavedRoutes/Auto/<profileId>/`，使用独立的版本 1 JSON 和原子替换写入。保存原始点位标识、真实坐标、起点来源、访问顺序和跳过历史；`active.json` 指向该档案的活动路线。现有手绘路线格式及加载方式保留。
- 完成状态始终以现有本地标记记录为准。文件损坏、身份或坐标不能解析时报告错误，不静默删除目标。

## 验证记录

以下为本机 Release 和隔离数据目录中的离线验证，不代表实际游戏验收：

- 完整原生 CoreHost、WinUI 构建及发布资源探针通过。
- 原生自动路线测试覆盖 0/1/500 点、ID 完整性、可重复性、固定起点、优化长度、取消、矩形与凹形/自交套索、边界、矩形/圆形线段裁剪、文件损坏与原子保存等。
- 真实 CoreHost 管道测试覆盖选点上限、过期请求拒绝、预览与活动路线隔离、完成保存失败、跳过及撤销、保存加载、重启恢复和档案隔离。
- 现有原生标记和优化回归、托管回归、WinUI 导航检查通过。具体测试入口、日志和 500 点性能结果见 [自动路线测试说明](../AutoRoutePlanningTests_20260908.md)。

实际游戏仍需验证鼠标与 Esc 接管、地图拖动、不同窗口尺寸/DPI、大小地图贴合、跨场景暂停及目标推进；规划开启前后的定位与绘制帧性能也需在同一游戏场景对比。当前未检测到正在运行的游戏，未将这部分记为通过。
