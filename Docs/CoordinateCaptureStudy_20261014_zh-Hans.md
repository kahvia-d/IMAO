# 同帧坐标与小地图采集：第一轮实机核验

> 追加实验：英文轻量模型的离线接入与对照见本文末尾“英文模型候选”。首轮结果仍保留原始取景与模型身份。

本轮完成 1160 对截图的完整性检查、两种 OCR 的离线回放和独立小地图匹配。
人工核对的 20 张 XYZ 中，PP-OCR contrast 在生产取景下完整命中 13 张，
专用单字符 YOLO 在生产取景下同样命中 13 张，使用底部四分之一像素带时命中 18 张。
取景与后续时间戳是影响结果的重要因素。小地图可提供近似 XY，尚不能直接作为精确数字标签。

## 素材与真值

会话为 `session-1F638949-A4DA-46C7-8131-3F08EEFD62FD`，客户区始终为 2560×1440，
本地时间 2026-10-14 14:03:58–14:13:57。左下角保存矩形 `(0,1312,640,128)`，
小地图保存矩形 `(48,37,246,246)`。共 1160 对、196379637 字节 PNG；
文件摘要、配对 ID、尺寸、结束计数均通过检查，无缺失或未索引文件。

从按时间分布的原图人工抄录 20 张完整 XYZ，先选 10 张无读数帧。
这些是有目的的小规模核验样本，不能据其比例估计全部场景的准确率。
其余帧不因模型返回读数而获得真值。

人工标注也有错误：第 710 帧的 y 初次抄为 -119，重新查看原始 PNG 确认为 -19。
保留初版标注和评测报告，在 revision 2 中更正并重跑评分。
之后审阅小地图匹配输出，发现 6 张大地图反例，在 revision 3/4 中登记为无读数。
这 6 张属于主动发现的反例，不能与预选 10 张混合解释为无偏误报率。

## OCR 对照

模型和解析器沿用独立离线评测管线。每帧三种取景都向两侧提供相同 BGR 像素，
没有把标签、小地图、历史真值或匹配位置交给 OCR。
20 张完整 XYZ 和最终 16 张无读数分别计分；其余 1124 张保持未知。

| 管线与取景 | XY 正确 | XYZ 正确 |
|---|---:|---:|
| PP-OCR contrast / production | 18/20 | 13/20 |
| PP-OCR TopHat / production | 13/20 | 11/20 |
| PP-OCR 双路线互证 / production | 13/20 | 11/20 |
| YOLO / production | 17/20 | 13/20 |
| YOLO / readout-wide | 17/20 | 17/20 |
| YOLO / upstream-band | 18/20 | 18/20 |

16 张已确认无读数上，各管线均没有输出坐标。
同一个生产框下，两种模型的 XYZ 命中都是 13/20；不能把取景扩大后的提升全部归于模型。
把 PP-OCR 输入直接放宽也没有获得同样收益：contrast 的 readout-wide 仅 1/20，
TopHat 为 10/20。应先分离完整坐标行与后续时间戳，再比较识别效果。

两个已标注的 YOLO upstream-band 未命中案例分别为：

- 第 710 帧：字符输出含正确的三个整数，但逗号缺失和时间戳污染使上游解析器拒绝输出。
- 第 1100 帧：把 y=-5388 读成 -5338，是字形错误，不能通过只修裁切解决。

全量未知帧的输出只用于发现问题，没有纳入准确率分母。
复核队列另发现 8 处 YOLO 与近似视觉坐标的大分歧，均为 x 的符号相反。
第 109、995 帧原图可见负号，而 YOLO 返回正 x，已登记部分符号真值；
其他分歧仍待逐帧核验。这些反例支持保留正式定位的负号与跳变门禁。

## 小地图匹配与误差

复用本机原生 `IMaoVisualRegression.exe`，输入只含小地图、样本 ID 和空 expected，
不提供 `worldHint`、OCR 提示或人工坐标，也不提供 trustedReference。
推理结束后才用人工读数计算误差。

首次整会话回放在第 304 帧超时，工具未保存此前结果。失败日志保留。
随后单独运行 20 张核验帧，并把其余帧按每批 40 张回放，全部 1160 张得到报告。
所有批次原生返回 3、`acceptancePassed=false`：正式发布门禁要求存在标签等条件，
而本轮刻意不给原生推理传标签。这个门禁没有被当作通过，也没有修改既有断言。
本轮只核对原始候选、配对完整性和外部标注误差。

候选要求结果与最高候选均为 Strong、无歧义、搜索完整并通过局部复核。
这只是一道研究用筛选，不代表候选已成为可信位置或准确标签。
按候选场景使用项目现有坐标变换，不能把子世界坐标一律套进 World 的原点。
原生程序目录与资源目录的场景标定文件摘要相同，转换记录见证据目录。

20 张人工 XYZ 中，7 张获得上述匹配。其 XY 欧氏误差为 0.64–3.10 个游戏坐标单位，
中位数 2.37；直接四舍五入后，只有 1/7 的 XY 与显示整数都一致。
这里只核验坐标分量，没有独立的场景身份真值；不能据此宣布场景识别准确。
小地图不提供 z。

World 的 4 张匹配帧用于一个单独的偏移实验，估计误差偏移为 x=-2.008、y=-1.221。
在另一张后续 World 帧上，修正后误差从 2.37 降到 0.36。
只有一张验证帧，且来自同一会话；该偏移没有写入标定文件，也没有用于候选标签。
其他场景没有足够锚点拟合偏移，当前误差范围也不是统计置信界。

## 大地图反例与候选集

第 537、665、916–919 帧实际是大地图界面，没有坐标读数或游戏圆形小地图，
却获得 Strong 并通过局部复核。例如第 919 帧有 33 个内点、约 0.42 的重投影误差。
地形块可以匹配正确，但它不是玩家小地图中心；匹配质量不能证明 HUD 身份。
这 6 张已从坐标候选中隔离，保留为标注链的反例。

最终保留 437 条尚无完整人工真值的近似 XY 候选，另有 687 条因无候选、非 Strong
或歧义而暂不使用；36 张人工 XYZ/无读数另存。
候选含原始双图路径、摘要、共同源帧时间、客户区几何、场景、浮点 XY 和匹配质量。
全部标为需要复核，`exactCoordinateLabelEligible=false`，z=null，
没有写入评测 corpus 的 expected，也没有生成精确自动标签。

复核队列按观测分为：16 条 YOLO 无输出、8 条视觉与 OCR 大分歧、
22 条 PP-OCR 与 YOLO 的 XY 分歧、391 条近似相符但仍未标注。
8 单位的分歧阈值只用于排序，不是标签可信门槛。
队列中也有无可见读数但仍有小地图的画面，不能靠视觉位置强行赋予数字 OCR 真值。

本轮最优先的后续工作是：

1. 独立定位坐标行的边界，保留长坐标与负号，同时排除后续时间戳。
2. 在辅助标注链确认游戏小地图身份，拒绝大地图地形块冒充玩家小地图。
3. 用本轮符号反例核验负号处理，并分场景、用更多独立会话验证标定误差。

这些工作应在离线管线验证后再考虑正式接入。当前没有刷新或发布客户端。

## 英文模型候选

后续按用户要求将官方 `en_PP-OCRv5_mobile_rec` 加入独立离线评测，使用原生 Paddle 3.0
依赖、现有预处理和解析器，不改 IMao 的正式模型与管线。英文模型配置保留原始名称，
436 个字典字符原序生成 `ppocr_keys.txt`，图输出的 438 类对应字典、CTC blank 和空格。
这仍是英文与符号模型，不是数字专用训练。

官方模型 archive 8,007,680 字节，只下载一次；本地模型和来源摘要存于
`C:\Dcode\WWMAP-TOOLS\out\coordinate-models\`。
接入方式、配置拒绝检查和命令见 [独立离线评测](CoordinateOfflineEvaluation_zh-Hans.md)。

英文模型在同一 1160 帧、三种裁切上完整回放，共 3480 个输入和 13920 条管线输出。
20 张完整 XYZ、16 张无读数和额外两张负号反例组成 38 张核验集；额外反例保持 UNKNOWN，
不新增完整坐标标签。当前模型、英文候选各重复三次；解码稳定，英文全量的核验样本
解码文本与所选坐标同三次回放一致，当前模型的核验解码文本与所选坐标同上轮一致。

| 取景 / 路线 | 当前通用模型 XYZ | 英文候选 XYZ |
|---|---:|---:|
| production / contrast | 13/20 | 14/20 |
| readout-wide / contrast | 1/20 | 18/20 |
| production / TopHat | 11/20 | 8/20 |
| production / 双路线互证 | 11/20 | 8/20 |
| readout-wide / TopHat | 10/20 | 13/20 |
| readout-wide / 双路线互证 | 0/20 | 13/20 |

各路线在 16 张无读数上均无输出；仍不能将此比例解释为无偏误报率。
production / contrast 的 XY 反而从 18/20 降至 17/20，不能只看 XYZ 的单张增长。
英文 contrast / readout-wide 的两个完整坐标错误是：190 的 x=-496 漏负号变为 +496，
1100 的 y=-5388 读成 -5338。模型分数分别约 0.946、0.973，高分并不保证正确。

已确认负号的事后难例 109、995 中，英文 contrast / readout-wide 都返回正 x；
当前通用模型分别读对 x 符号、拒绝输出。它们只用于符号回归，未混入 20 张 XYZ 分母。
结果支持保留英文 contrast 作为输入优化与游戏素材微调的候选，但不支持直接替换默认模型，
更不能通过放松负号、互证或跳变门禁来提高输出率。

有效证据位于 `C:\Dcode\WWMAP-TOOLS\out\coordinate-english-comparison\`：

- `english-full-venv/`：项目既有虚拟环境下完成的全量回放与前后模型/代码摘要。
- `english-audit/`、`current-audit/`、`audit-corpus.json`：38 张、各重复三次的对照。
- `comparison-report.json/.md`、`build_comparison_report.py`：逐路线比较、原始报告摘要、重复一致性与符号反例。
- `english-full/`：首次误用系统 Python 的失败尝试；原生回放完成，YOLO 在 NumPy.typing 处失败，未生成有效完整报告，未用其生成正式对照。
- `final-tests.log`：61 项测试通过，含四项真实原生模型拒绝加载测试。

原生独立工具构建通过，代码与数据经过独立复核。推理耗时记录在报告中，但本机负载、
评测顺序和运行环境影响时间，不能据此推断游戏帧率。全部样本来自同一会话，尚无独立验收集。
下一轮优先改善完整坐标行输入和负号保留，再决定针对游戏字体与背景的专用微调方案。
