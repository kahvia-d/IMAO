# 查漏补缺模式与名录维护

查漏补缺是全局地图筛选偏好，默认关闭。开启后，普通标记为原筛选与已确认不可探测名单的交集，大小地图同步；切图、退出导航和重启保留。已有路线目标与导航指引不改写，新增选点遵循过滤后的可见集合。清单外是未知，不是可探测。

## 维护入口

- `tools/MarkerDetectability/catalog.json` 是唯一收录入口；初次从视频时间轴审核导入 378 个去重身份。
- 每项 `stateId`、`pointId` 都是字符串；保留 `sources`（视频、分P、事件、成员或集合）、`reviewBasis` 和 `notes`。
- 集合确认对每个 ID 收录同一来源集合，成员为 null，不臆造逐箱顺序。任务前置引导晶核不收录。
- 用户确认和缺少攻略图片的事实必须保留。新增项应附明确身份确认依据；疑似点位留在离线审核中，不进入名录。
- 历史视频证据仍在 `tools/MarkerDetectabilityV2` 及本地缓存中；程序不加载或分发这些视频、图片和转写。

## 新增、撤销与改配

1. 审核来源及点位身份，再修改维护名录。撤销删除对应项；改配同时更新身份、来源和说明。
2. 运行 `python tools/MarkerDetectability/generate.py`，生成稳定排序的 `Assets/KuroMap/marker-detectability.json`。
3. 运行 `python tools/MarkerDetectability/generate.py --check` 和 `python -m unittest discover -s tools/MarkerDetectability`。
4. 一并审阅名录与生成清单的差异，不手改生成文件。378 是初始验收数量，不限制后续新增。

更新库街区点位数据后也必须运行检查。失效 ID 会报错，应先核对上游是否迁移/合并，再明确改配或撤销；不能按最近坐标自动替换。

## 分发与失败行为

运行时只读取当前资源快照 MapDataRoot 下的生成清单，随现有 map-data 包复制、校验与更新。清单格式为 schemaVersion=1、states 对象（state 字符串映射到 pointId 字符串数组）。程序启动或资源快照重新初始化时加载一次，不在渲染循环读盘。

清单不存在、版本不支持、重复或身份不存在均使清单不可用；开启状态下隐藏普通点位并显示可关闭模式的提示，同时写诊断。关闭后原分类筛选与完成记录恢复正常，不修改路线或用户进度。
