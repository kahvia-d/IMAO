# 短时完整采集可靠性修改计划

目标：在有限内存下改善旧电脑的持续无损采集能力，明确区分采集时间与排空时间，并交付可独立解压运行的测试包。用户已授权先完成计划再实施和打包。

## 设计与约束

- 保持原图像素、原序号、时间戳、上下文和 records.jsonl 顺序；不悄悄丢帧、不阻塞捕获线程等待磁盘、不放宽定位规则。
- 保持默认 256 MiB 证据预算、三分钟采集上限及 64 GiB 磁盘预算。任何机器持续生产超过消费能力时仍可能提前停止，不承诺任意硬件满速三分钟。
- 现状每个排队图都按原图三倍收费，实际只有一个条目在编码。改为每个条目保留原图/元数据预算，另为单个编码器保留本次最大编码工作区；入队前核算总和，包含正在处理的图。保留保守编码余量，不将预算当实际进程内存承诺。
- XPRESS 四块文件格式不变，以四个常驻编码线程及各自压缩句柄替代每张图创建线程/句柄。图像仍按顺序写入，结束和失败均等待已有工作完成。
- PNG 格式保持兼容，使用面向快速无损编码的 RLE 策略；通过像素往返和实际图像测试确认。日志流按时间批量 flush，结束必须 flush/close，减少每条记录刷流的开销；这不是掉电级持久化承诺。
- 状态增加峰值预算、入队图数、单图编码与写盘总耗时和接收截止时间。失败提示解释“提前停止、后续未采集”，保留原错误详情；不得把 missingImages 当整个计划时长的缺失总数。
- 保留前一提交的小地图修复。新测试版本 `2026.10.31.101`，不发布正式更新，不改玩家安装，不覆盖正在运行的测试树，不下载大文件。

## 执行任务

### 1. 队列预算与停止状态
- [ ] 先增加预算模型和截止时间测试，证明旧实现不具备新的预算/状态语义。
- [ ] 实现独立、可测试的入队预算计算：排队像素与元数据 + 单个编码工作区；检查溢出、单图超过预算、不同尺寸交替、日志条目及排空归零。
- [ ] 记录峰值和接收截止时间，终态采集时长不包含写盘排空；旧 elapsedMs 保留总耗时兼容。

### 2. 无损写入吞吐
- [ ] 加入常驻四线程 XPRESS 编码器，不改变四块容器及解码格式。
- [ ] 使用快速 PNG 策略，周期性 flush records；结束/异常仍有完整性标志。
- [ ] 运行现有拥有权、重启、旧异步 scope、磁盘不足、并发序号与灰/BGR/BGRA 像素一致性测试。
- [ ] 加入33ms全帧与识别裁剪/日志混合压力测试，记录吞吐、提交延迟、队列峰值；不以只含小图的单测替代性能结果。

### 3. UI 与诊断
- [ ] 扩展托管状态字段并兼容旧核心；失败明确区分停止接收与保存排空。
- [ ] 显示已记录时长、队列峰值及提前终止说明，队列满错误给中文解释，其他错误保留原始信息。
- [ ] 真 WinUI publish，自包含，不用托管测试代替 XAML/WinUI 构建。

### 4. 交付
- [ ] 独立审查代码，补齐发现的问题，记录测试与已知性能边界。
- [ ] 使用项目整树打包脚本生成独立测试程序，载荷包含 resources.pri、includedFrameworks 和一致版本的资源快照；资源使用本地已有等价物。
- [ ] 校验整树文件、联接及版本，ZIP 可在旧电脑独立解压运行，给出 SHA256。
- [ ] 附测试步骤：同一场景分别不开采集/开采集，对照1080p和原分辨率；保留整个采集目录及日志。低性能机器如仍失败，峰值/耗时足以区分生产过快与写盘慢。

## 重点复核

1. 预算不能只计算队列、漏掉正在编码的原图和编码缓冲。
2. 停止、超时、失败和重新开始不能死锁或混入上一场采集。
3. 无损格式必须保持现有解码工具兼容，写盘失败不得宣称完整。
4. 新状态字段在旧核心下缺省值必须安全，时间不得把排空误当录制。
5. 旧电脑性能验证尚未发生，不能把本机压力测试当作旧电脑验收。

## 实施记录

- 状态断言先在旧实现上失败，新增实现后基础回归通过。
- 已实现共享编码工作区预算、四线程/句柄复用、独立采集截止时间、峰值与单图处理耗时、中文提前终止说明。
- Ruling：取消批量 flush，保留逐条 flush。独立审查指出批量缓存最终刷盘失败会高报 saved 数量；本次优先保持可靠失败计数，不引入批次确认机制。
- 增加常驻压缩句柄多轮独立解压校验与 33ms 全帧/裁剪/识别/日志混合压测。
- 首轮本机真实历史 2560×1440 BGRA 图像压测：300 全帧 + 300 裁剪，全部保存；约9.9秒，3.70GB，预算峰值约57MiB。最终保留逐条 flush 的版本将再次测量。该测试不是三分钟实机验收。

- 最终逐条 flush 版本基础回归通过；1440p 压测两轮分别在5.32秒/7.99秒停止接收，最终保存322/484张，单图最大处理耗时1.73秒/3.57秒。此结果明确暴露大图约370MB/s写入和秒级停顿无法由256MiB预算持续吸收；没有静默丢弃、没有把停止后的张数伪计为缺失1张。无法据此判定是磁盘、杀毒还是调度停顿。保留这些失败证据作为旧电脑测试边界，不将首轮通过作为保证。
- 本次不降低采样频率、不改有损格式、不提高旧电脑内存上限：这些属于采集能力取舍，需要额外需求确认，不混入确定问题的修复。
