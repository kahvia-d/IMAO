# 手绘自由点：本地进度、类型和地图显示

## 玩家规则

新路线选择「收集物」或「非收集物」，加入第一个点后锁定类型，保存或放弃后才可新选。
收集物只允许数字图标，完成记录长期保留；非收集物允许数、怪、1C、3C、植、矿，完成记录按现有游戏日规则在本地凌晨 04:00 刷新。
连接官方点时保留官方身份与图标，并校验类型：收集物仅连接官方收集物，非收集物仅连接敌人或采集物。拒绝操作不会生成替代自由点。

绘制时，大地图左侧图标栏只改变随后添加的自由点。「怪」悬停展开第二列，父节点、1C 和 3C 都能选择。
Esc 保留草稿，Ctrl+Z 撤销最后一个点，继续绘制保留类型和所选图标。

保存并应用路线后，自由点可通过当前目标完成、地图点位操作、附近点位键盘/手柄入口完成；自由点与标准点位共用详情页、鼠标右键切换及手柄圈选操作，取消完成不在路线列表单列按钮。
完成记录与跳过记录独立。非收集物自由点仅在玩家主动启用「刷怪采集」后自动完成；收集物始终手动确认。
自由点说明使用本地信息，不请求库街区攻略。

## 存储与兼容

路线文件和导出包写版本 2，继续读版本 1。图标值固定为 `number / monster / monster1C / monster3C / plant / ore`，分类值为 `collectible / daily`。
`StopKind::Free` 不携带官方 `nameId`。完成身份使用 `stateId:free-route:<routeId>:<pointId>`，显示序号由路线顺序计算。撤销不回收已使用的点 ID。

本地账本位于应用数据目录 `SavedPoints/profiles/<profile>.free.json`，schemaVersion 为 1，分为永久和每日记录。
每日记录复用 `FarmCompletionStore::CurrentEpoch()` 的游戏日计算。账本独立于官方完成文件、云端合并和待上传队列，导出包也不包含账本。
写入采用现有原子替换机制，写入失败不会更新内存完成状态或推进当前目标。

旧自由点默认每日刷新和数字图标，按原路线和原点 ID 确定性补足身份，跳过集合及撤销历史一起迁移。
旧混合路线进入兼容模式，保留顺序、坐标及官方点位。
导入为新路线和覆盖合集都会生成新的自由点 ID 并重写引用；覆盖活动路线时先失效旧导航。重新规划的新路线也重新绑定自由点 owner。

## 渲染与验证

大地图和小地图共享圆形文字标记。已保存自由点进入大地图的标准标记布局、重叠展开和操作流程；已完成点在显示已完成点的设置开启时保留并以 45% 不透明度变暗，包括文字。小地图仍按标准点位规则隐藏已完成点，路线标记快照独立于线段，最后一个目标仍显示。跳过只改变导航目标，不移除大地图上的自由点。
复用路线帧、档案、场景、路线版本、运动补偿和定位新鲜度检查。边缘标记对纹理三角形执行圆形裁剪，包含文字、外环和抗锯齿边缘。
草稿和待保存路线只在大地图显示。

针对性回归覆盖稳定身份、跨路线/档案隔离、重启与关闭程序跨日、原子写入失败、v1/v2 跳过历史迁移、六种图标、类型拒绝、完成/取消/自动门控、重新规划与覆盖导入、单目标快照、圆形纹理裁剪和手柄身份校验。
使用 `scripts/Test-Runtime.ps1`、`ctest`、ManagedRuntime、MapToolsRuntime 和 RoutePageRuntime；构建 CoreHost 和 WinUI 自包含输出。构建及部署证据写入忽略目录 `out/free-point-work`。
实机验收需在运行游戏时检查大地图图标栏、怪物子菜单和小地图标记、各类完成/取消操作及定位中断恢复。
