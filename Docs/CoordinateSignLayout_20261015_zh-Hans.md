# IMao 坐标符号：固定 X 起点与 Y 相对间距校验

用户提出两条布局线索：X 首位数字相对固定左起点的位置，以及 Y 首位数字相对 X 末位数字的距离。本轮把它们实现为独立的离线校验器，**只拒绝可疑返回，不补负号、不新增坐标返回**。

同一自训权重和 [XY 解码器](CoordinateOwnYoloXY_20261015_zh-Hans.md)，170 张开发图由 **153 正确／1 错误／16 未返回**变为 **153 正确／0 错误／17 未返回**。雪地 1071 帧的漏 X 负号被挡住，但没有被修复为正确坐标。所有原来正确的 153 张均保留，141 张无坐标仍零误报。真实 Y 漏号没有新增已标注案例，本轮用单独的删检测框实验检查其行为，不把模拟结果当真实准确率。

## 依据与限定范围

本轮查看了六张已有正 X 历史训练来源。五张为 2560×1440，字体、坐标行和当前固定 ROI 可比；另有一张 1920×1080，明确不纳入本次布局校准。历史来源不是新采截图，也没有当作额外独立会话验收。

固定预处理为原始帧 `[32,1405,608,33]`，实际原生程序输出 892×48 原色图，左右各 4 像素边框。历史输入也经现有已编译原生程序实际预处理；随后只用本项目自训 YOLO 检测，不调用网友权重、字符框或伪标签。

新增 `tools/coordinate-ocr/sign_layout.py`。它接收已有 XY 返回、检测框、冻结校准记录和调用者明确提供的布局配置。当前只覆盖上述帧尺寸／ROI／观察字体。它没有动态判断 HUD 布局的能力，也不能仅凭图片尺寸保证游戏 UI 设置没变。

对于不同配置、图片尺寸或超出校准带的字体宽度，返回明确的 `applied=False` 诊断并保留基础结果；这表示**布局规则没有应用**，不是“通过布局校验”。本轮没有把该分支接入正式客户端。

## 特征与校准

为减少 `1`、`8` 可见笔画宽度差异的干扰，使用检测字体框的中心，按去重后数字框宽度中位数归一化：

- X 特征：`(X 首位数字中心 - 4 像素预处理边框) / 数字框宽度中位数`。
- Y 特征：`(Y 首位数字中心 - X 末位数字中心) / 数字框宽度中位数`。它跨过逗号及可能的 Y 符号，不依赖 X 有几位数。

只从基础解码器选中的完整 `X,Y,` 前缀提取对象，使用与基础解码一致的过滤、同类去重和空间分组。没有从正确答案选择检测框。

校准候选为原有 67 张自训图，以及 3 张原 train 分区的正 X 历史锚：laguna、lowervault、timeriftruins。排除基础 XY 没有正确返回的 3 张，实际用 **64 张原训练图 + 3 张历史锚 = 67 个样本**。X 正／负为 3／64，Y 非负／负为 28／39。全部属于既有 train，开发集和 776–787 整组没有进入校准，第 1100 帧也未使用。

每种符号布局的带宽取训练观测最小、最大值，再向两侧各扩展“正负布局间空隙的四分之一”；字体宽度范围取训练最小值×0.8 至最大值×1.2。先冻结 `calibration.json`，才对开发集应用规则，没有用开发结果调阈值。

| 归一化特征 | 无符号布局带 | 有符号布局带 |
|---|---|---|
| X 首位起点 | 1.561–1.932 | 2.240–2.669 |
| Y 相对间距 | 1.309–1.620 | 1.872–2.294 |

Y 训练实测中位数约为无符号 1.45、有负号 2.12，确实存在可分离的距离差。X 的正数样本较少，不能据此声称已覆盖所有正 X 字体和界面设置。

运行时，若已经明确识别出正负号，不因这条几何规则改写符号；没有符号时才检查是否符合无符号布局。落在有符号带或其它不明位置，标为可疑并拒绝本次 XY。距离异常也可能是漏数字、框偏移或界面变化，不能唯一证明缺的是负号，因此不会按位置直接补号。

## 真实图结果

冻结权重和原有检测框不变，新增布局校验只撤销返回。开发集合仍为 170 张有坐标、141 张无坐标、8 张待定；67 张训练来源分开统计。

| 实际图分组 | 基础 XY：正确 / 错误 / 未返回 | 布局校验后 |
|---|---|---|
| 开发坐标 170 张 | 153 / 1 / 16 | **153 / 0 / 17** |
| 雪地混合 40 张 | 32 / 1 / 7 | **32 / 0 / 8** |
| 草地整组留出 776–787，12 张 | 12 / 0 / 0 | 12 / 0 / 0 |
| 训练来源 67 张，仅拟合统计 | 64 / 0 / 3 | 64 / 0 / 3 |

141 张无坐标均未返回。8 张待定由 3 张返回变为 2 张返回：508 帧也被布局检查拒绝，但不判为“修复了错误”，不据此改标签。

1071 帧中，没有检测到 X 的负号，但首位数字仍在有符号位置，X 特征约 2.404，因此拒绝原来的正 X 返回。其 Y 已观察到负号，未因间距而改写。这里的收益是减少错误返回，不是增加正确识别数。

## 正 X 检查

另外两张同尺寸历史正 X 图 qiqiu、blackshores 没有参与校准。它们的首位起点特征约 1.750、1.764，均落在正 X 带：

- blackshores 的基础正确 XY 返回保持不变，没有误拒。
- qiqiu 本来因缺失 Y 结束逗号而未返回；这里只能确认其首位位置诊断兼容正 X，不能把它算作端到端通过。

三张校准正 X 图的正确返回也均保留。1920×1080 的 black-shores-gameplay 明确显示“未校准配置”，保留基础返回但不算布局检查通过。没有以单个 1080p 图片宣称跨分辨率通用。

## 删负号框的对照实验

保留原图、原始检测结果和真值不变，另复制检测列表，只移除已观察到的 X 或 Y 负号框，所有数字框的位置、类别、分数保持原样。目的是检验“模型漏掉符号但数字位置保留时，布局能否发现”。**没有改图片、没有重跑出这样的真实 OCR 错误，也没有将其计入真实开发准确率。**

最终仅统计原来 XY 正确的开发来源，避免把已有 X 错误混进 Y 漏号效果：

| 检测框对照 | 来源数 | 基础解码错误返回 | 布局校验拒绝 | 补成正确负数 |
|---|---:|---:|---:|---:|
| 移除 X 负号 | 153 | 153 | 153 | 0 |
| 移除 Y 负号 | 62 | 62 | 62 | 0 |

全部来源生成的 322 个对照也保存了，训练来源和待定来源没有混进上表。初稿曾把本来 X 已错的 1071 帧计入 63 个 Y 对照；最终 `report-v2.json` 明确剔除该条，原始初稿保留，未改写标签或真实图成绩。

## 验证与后续

新增 11 项测试，先用未实现入口观察 11 个失败，再通过实现；覆盖正常正数、X／Y 漏号、显式正负号、X 位数变化、未知配置、字体变化、基础未返回、位置异常和同类重复框。离线全套 104 项中 90 通过，14 项依赖额外运行环境的集成测试明确跳过。未修改旧断言、基础解码器、训练权重或玩家目录。

核验冻结校准全部来自 train、392 条实际输入回放、322 条删框回放、数字框未变、真实图计分、旧权重与解码器摘要。对上一轮实际 CPU ONNX 已保存的 386 组检测框应用同一校验，与 PyTorch 检测框的 XY 返回、启用状态和可疑轴全部一致；本轮没有把复用缓存称为重新运行 ONNX 网络。独立审阅未发现阻断问题。

这条规则适合继续作为当前布局的保守离线保护。下一步若扩大适用范围，需要更多未参与校准的真实正 X、真实 Y 漏号，以及不同 UI 缩放下的对照；当前不把训练中的三个正 X 或重复使用的开发集当最终验收。
